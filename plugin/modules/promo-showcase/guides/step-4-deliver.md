# Шаг 4. Проверка, рендер, выдача

Когда: композиция в `$WORK/<проект>/build/` собрана, надо проверить её, отрендерить `promo.mp4`, выбрать кадр-обложку и написать подпись к посту.

## Проверка

```bash
npm --prefix engine run check -- "$WORK/<проект>/build"
```

Исправь все ошибки, включая провалы контраста WCAG (они ошибки, а не предупреждения). Каждая находка по контрасту содержит предложенный подходящий цвет: примени его или подбери в той же палитре и запусти ещё раз. Проверка раскладки подстраховывает закон «весь текст читается»: исправь сообщённое переполнение.

Прочитай и охват проверки. Если в композиции есть видимый текст, а проверено `0/0` текстов, контраст не проверен, даже если проверка напечатала «passed». Найди причину (например, неподдерживаемые цвета `oklch()`: переведи их в эквивалентные `rgb()` или hex, проверь, что палитра не изменилась) и запусти снова. Продолжай, только когда нужный текст действительно проверен.

Быстрый взгляд на ключевые кадры перед рендером:

```bash
npm --prefix engine run snapshot -- "$WORK/<проект>/build" --at 1,4,7,12,18
```

Смотри кадры каждой сцены и середины каждого перехода, брать время середины из таймлайна (конец ухода одного элемента и начало входа следующего), а не на глаз. Простой «растворяющийся» переход между двумя плотными раскладками даёт мутную двойную экспозицию: разведи по времени (старое ушло, потом новое пришло) или проведи через фон.

## Рендер

Покажи человеку черновик и, если он одобрил, делай рендер:

```bash
# черновик, быстро
npm --prefix engine run render -- "$WORK/<проект>/build" --quality draft --fps 30 --output "$WORK/<проект>/out/promo.mp4"
# итоговый
npm --prefix engine run render -- "$WORK/<проект>/build" --quality high --fps 30 --output "$WORK/<проект>/out/promo.mp4"
```

Проверяй сам файл, а не только кадры: число кадров равно длительности умноженной на fps, кадр в известный момент показывает то, что план говорит. Рендер может завершиться без ошибки и потерять кадры (например, когда PNG-кадры наложения посреди последовательности переключаются между RGB и RGBA): приведи такую последовательность к одному формату пикселей.

## Кадр-обложка

Обложка — неподвижная картинка до начала воспроизведения. Не оставляй её первому кадру или случайному времени: они попадают на затухание, середину перехода, пустой фон или недорисованный текст.

Ты сам собрал композицию и знаешь сильнейший момент и когда он наступает: хук, главный показ или финальный знак. Выбери этот миг в **устоявшейся** точке: текст полностью вошёл и ещё не ушёл. Достань кадр в полном размере:

```bash
# время сильнейшего устоявшегося момента, например 3.2 с
ffmpeg -ss 3.2 -i "$WORK/<проект>/out/promo.mp4" -frames:v 1 -q:v 2 "$WORK/<проект>/out/promo.jpg"
```

Кадр должен быть пригоден к публикации сам по себе. Если он попал на переход или середину анимации, сдвинь время на несколько десятых секунды и достань снова.

### Вшить обложку первым кадром

У голого `.mp4` нет понятия обложки: каждый плеер и площадка берёт свою картинку покоя, почти все берут **кадр 0**. Чтобы обложка была везде одинаковой, сделай кадр 0 обложкой: замени пиксели только первого кадра, остальные кадры, всё время и звук не меняй. На 30 кадрах в секунду обложка видна 1/30 с, на воспроизведении это незаметно, но именно её видят все генераторы миниатюр.

```bash
cd "$WORK/<проект>/out"
ffmpeg -y -i promo.mp4 -i promo.jpg \
  -filter_complex "[0:v][1:v]overlay=0:0:enable='eq(n,0)'[v]" \
  -map "[v]" -map "0:a?" -c:v libx264 -crf 18 -preset slow -pix_fmt yuv420p \
  -c:a copy -movflags +faststart promo.poster.mp4 \
  && mv promo.poster.mp4 promo.mp4
```

`promo.jpg` оставь рядом: это файл для площадок, где обложку загружают отдельно.

## Подпись к посту

Напиши `out/share-copy.txt`: одна-три фразы, готовые к публикации как есть, конкретные для проекта, в тоне ролика. Без «рады поделиться». Один канонический текст; варианты для разных площадок и длинные анонсы идут в отдельный необязательный `share-copy-variants.md`.

Заготовки по тону:

- **`default`**: «Сделал [название]. Это [что делает, странными словами самого проекта]. [Лучшая строка из продукта.]»
- **`polished`**: «[Название]: [чистая строка с сайта]. Сделано на [стек, если примечателен].»
- **`yc-parody`**: «Мы сделали [название], чтобы решить [проблема, сказанная всерьёз]. [Сухая функция или цифра.]»
- **`chaotic`**: «[ЗАЯВЛЕНИЕ КАПСОМ]. [Название] — [дико преувеличенное описание]. Ссылка ниже.»
- **`deadpan`**: «Сделал [название]. Оно [что делает].»
- **`cinematic`**: «[Название]. [Слоган с сайта, дословно или чуть адаптированный.]»
- **`app-store`**: «[Название] теперь доступно. [Функция 1], [функция 2] и [функция 3] в одном месте.»

## Итоговая раскладка

```
$WORK/<проект>/
  promo-plan.md           план и раскадровка
  composition-brief.md    задание на сборку
  build/                  композиция
  out/promo.mp4           готовый ролик
  out/promo.jpg           кадр-обложка
  out/share-copy.txt      подпись
```

Скажи человеку: где ролик, где подпись, одну фразу о творческом ходе; предложи пересобрать сцену, сменить тон или попробовать другой ракурс.
