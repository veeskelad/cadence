# Скриншоты и превью-видео приложения для магазинов

**Когда брать:** человек делает мобильное приложение и просит скриншоты для App Store или Google Play, видео-превью приложения или хочет поменять готовые: подписи, фон, рамку устройства, порядок кадров.
**Что дать:** собранное приложение (Release-сборка для симулятора iOS или APK для Android), название и пару слов о том, что оно делает; подписи агент может написать сам.
**Команда:** `GOLDIE_CONFIG=$WORK/<проект>/goldie.config.ts bun modules/promo-motion-kit/src/cli.ts all` (по шагам: `doctor`, `capture`, `frame`, `preview`, `manifest`, `verify`).
**Что получится:** в `$WORK/<проект>/out/` готовые PNG в рамке устройства с подписями (размеры магазина), видео-превью из записей экрана, `store.json` и проверка по правилам магазина. По желанию страница-витрина (студия) с выгрузкой zip.

Это не рекламный ролик: превью-видео для App Store склеено из чистых записей экрана без рамки и подписей (так требует магазин). Рекламный ролик о приложении — `promo-showcase`.

## Что нужно на машине

- `bun`, Node 20+, `ffmpeg`. Для iOS: Mac с Xcode и симулятором. На Linux и Windows работает только Android-устройство (`pixel-10-pro`), эмулятор должен быть настроен.
- Зависимости: `python3 scripts/module_setup.py status promo-motion-kit`; установка (`install`) ходит в сеть, только с согласия человека.
- Модуль не меняет репозиторий приложения: конфиг, сценарии и результат лежат в `$WORK/<проект>/`.

## Порядок работы

Подробный порядок с командами и таблицей «просьба → что править» — [guides/goldie.md](guides/goldie.md). Коротко:

1. Узнать, для какого магазина (если в проекте есть и iOS, и Android, спросить, не предполагать).
2. Найти Release-сборку приложения для симулятора; Debug рисует служебные плашки в кадр.
3. Пройти приложение, выбрать 4–5 экранов для скриншотов и 3–4 отрезка для превью.
4. Написать `goldie.config.ts` ([guides/config.md](guides/config.md)) и сценарии `flows/*.yaml` ([guides/flows.md](guides/flows.md)); подписи короткие, про пользу.
5. `doctor`, потом `capture` и `frame`; сломавшийся сценарий чинить по тексту ошибки.
6. `preview` (минуты), `verify`: сказать человеку, какие файлы есть и проходят ли правила магазина.

## Устройства и шаблоны

- `iphone-6.9` (iPhone 17 Pro Max, обязательный размер App Store), `ipad-13`, `pixel-10-pro` (Google Play).
- Рамки: три цвета iPhone, два цвета iPad, рамка Pixel. Шаблоны раскладки полосы кадров: `editorial`, `showcase`, `magazine`, `storyboard`, `dynamic`.
- Шрифты в комплекте: DM Mono, DM Sans, Lato, Merriweather, Montserrat, Noto Sans Arabic (лицензия OFL, `assets/fonts/OFL.txt`). Китайского шрифта Noto Sans SC в модуле нет (по 8 МБ на начертание): для иероглифов подключить свой через `theme.fontFiles`.
- Рамки устройств лицензированы отдельно (CC BY 4.0 и Apache 2.0): условия и авторство в `assets/ATTRIBUTION.md`. Публикуя скриншоты, сохрани указание авторства рамок, если лицензия этого требует.

## Ограничения

- Видео-превью для App Store: 15–30 секунд в сумме; без рамок и подписей. Для Google Play видео делается портретным, на YouTube человек выкладывает его сам.
- Пока работает `capture`, симулятор занят: параллельно с ним ничего не запускать. После работы симулятор гасится по правилам среды (если команда отклонена, дать человеку команду с UDID).
- Драйвер симулятора (`argent`) ставится как обычная зависимость пакета. Отдельный сервер агента для него (MCP) модуль не ставит: нужен ли он для осмотра приложения, решает человек.
- Если в экранах приложения есть данные людей, перед скриншотом заменить их выдуманными.
- Результаты и все промежуточные файлы в `$WORK/<проект>/`; исходники приложения не меняются.
- Модуль проверен смоук-тестом (паспорт, синтаксис); съёмка на настоящем симуляторе здесь не прогонялась.
