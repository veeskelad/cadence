# Модули Cadence

Модуль — готовый код под одну задачу: нарезка, шортсы из длинного, эксплейнер, промо, озвучка. Агент
не выбирает модуль сам по себе: вход всегда навык-семейство из `skills/` (`cadence-cut`,
`cadence-motion`, `cadence-sound` и другие). Навык показывает таблицу своих модулей, агент открывает
`MODULE.md` нужного и запускает его команду.

## Раскладка

```
modules/<id>/
  module.json   паспорт: семейство, когда брать, вход, выход, команда, зависимости
  MODULE.md     инструкция агенту: когда, что дать, команда, что получится, ограничения
  ...           код модуля (scripts/, src/, templates/, tests/)
modules/CAPABILITIES.json   функция → основной исполнитель → запасной (без двойников)
modules/REGISTRY.json       собирается скриптом, руками не правится
```

## Правила

- Один источник правды — `module.json`. `python3 scripts/build_registry.py` пересобирает
  `REGISTRY.json`, `MODULE-MAP.md`, таблицу маршрутов в `knowledge/system/ROUTING.md` и раздел
  «Модули» в навыке семейства. `--check` в тестах падает, если что-то не пересобрано.
- Одна функция — один основной исполнитель (`CAPABILITIES.json`): модуль или скрипт Cadence.
  Запасной берётся, только если основной недоступен.
- Модуль не регистрируется как навык: внутри нет `SKILL.md`, только `MODULE.md`.
- Рендер — только общий движок `engine/` (HyperFrames). Remotion в модулях не используется (решение владельца 16.11.2026):
  модуль на нём переписывается под `engine/`, `build_registry.py` не примет `"engine": "remotion"`.
- Зависимости — `python3 scripts/module_setup.py status|install <id>`: в общий кэш
  `~/.cache/cadence/modules/`, сеть только с согласия человека.
- Модуль тяжелее 3 МБ в выпуск едет лёгким: паспорт, `MODULE.md`, `guides/` и лицензии. Остальное
  `scripts/module_pack.py build --tag modules-<версия>` собирает в пакет для GitHub Releases и пишет
  в паспорт поле `payload`; `module_setup.py install <id>` скачивает пакет только с github.com,
  сверяет размер и sha256 и ставит ссылки в папку модуля. В исходниках папки лежат на месте.
- Пути — через `scripts/cadence_paths.py` (`work_root`): исходники человека не меняются,
  результат — `$WORK/<проект>/out/`.
- Сеть во время работы и ключи сервисов — выключены по умолчанию, поле `network` и `keys` в
  паспорте; агент спрашивает человека до первого вызова.
- Демо-видео, кэши, выходы, `node_modules` в репозиторий не кладутся.
- `MODULE.md`: главное в первых строках (когда брать, команда, что получится); длиннее 100 строк — оглавление в начале; ссылки на справку модуля — на один уровень, без цепочек.
- `when` — слова человека, не механика; в `not_for` — соседний модуль или навык, с которым путают.

## Паспорт `module.json`

| Поле | Что |
|---|---|
| `id` | имя папки, `[a-z0-9-]` |
| `family` | навык-вход из `skills/` |
| `title` | короткое имя по-русски |
| `what` | что получится, одна фраза |
| `when` | 2–8 типовых просьб человека его словами |
| `not_for` | с чем путают и куда отправить вместо этого |
| `capabilities` | ключи из `CAPABILITIES.json`, которые модуль исполняет |
| `inputs`, `outputs` | что дать, что появится |
| `run` | команда запуска от корня Cadence |
| `engine` | `python`, `node`, `hyperframes`, `ffmpeg`, `nim`, `docs` |
| `deps` | `python` (файл requirements), `node` (папка с package.json), `system` (программы) |
| `install_mb` | примерный объём установки |
| `platform` | `macos`, `linux`, `windows` |
| `network` | `none`, `install` (только установка), `runtime` (во время работы) |
| `keys` | имена нужных ключей сервисов, по умолчанию пусто |
| `status` | `ready`, `beta`, `docs` (только знания, без кода) |
| `payload` | пишет `module_pack.py`: `paths`, `file`, `sha256`, `bytes`, `expanded_bytes`, `url`; руками не править |
