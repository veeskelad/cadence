# Логотип и фирменный знак

**Когда брать:** человек просит логотип, монограмму, значок приложения, фавикон или хочет, чтобы ты посмотрел его готовый знак.
**Что дать:** название и бриф (чем занимается, 3-5 прилагательных, конкуренты, где знак будет жить); для проверки и вариантов — свой знак в SVG.
**Команда:** `python3 modules/logo-craft-skill/scripts/svg_audit.py <знак.svg>` (проверка файла); остальные скрипты в таблице ниже.
**Что получится:** файлы в `$WORK/<проект>/out/` (`--project <имя>` выбирает папку): обзор концептов, тест-лист, презентация, варианты знака, иконки.

Зависимостей нет: скрипты на чистом Python 3. Чтобы получить PNG, нужен любой из рендереров: cairosvg, rsvg-convert, Inkscape или Chrome/Chromium (`python3 modules/logo-craft-skill/scripts/render_png.py --which` покажет, что есть). Без рендерера SVG и HTML всё равно создаются. Сеть и ключи не нужны.

## Порядок работы

Полный процесс (режимы «новый знак», «разбор», «редизайн», «система», «файлы из готового знака») описан в [guides/logo-design.md](guides/logo-design.md). Коротко:

1. Бриф: название, чем занимается, прилагательные, конкуренты. Спроси не больше пяти вопросов за раз или назови допущения и иди дальше.
2. Восемь-двенадцать идей по одному предложению, выбери три самых разных и построй их в SVG: сначала чёрным на белом, без `<text>`.
3. Смотри на результат глазами: `render_png.py` -> открой PNG. Рисование кодом вслепую ошибается.
4. Проверь и доработай (минимум два круга): `svg_audit.py`, потом `preview_sheet.py`.
5. Покажи концепты одной картинкой `concept_sheet.py` (сначала в серых тонах) и остановись: набор файлов собирай только после выбора направления и слова человека.
6. После «да»: цвет, горизонтальная и вертикальная версии, презентация, файлы и короткие правила применения.

## Скрипты

Все лежат в `modules/logo-craft-skill/scripts/`.

| Скрипт | Что делает |
|---|---|
| `svg_audit.py <файлы.svg>` | Проверка знака: живой текст, растр, фильтры, число цветов, мелкие детали, «почти ровные» углы, центровка, сложность |
| `preview_sheet.py <файлы.svg> [--refs <чужие знаки для сравнения>]` | HTML-лист: лестница размеров, 16 и 32 пикселя, фоны, один цвет, размытие, зеркало, фавикон, шкаф конкурентов |
| `concept_sheet.py <знаки.svg> --names ... --notes ... --recommend 1 --greyscale` | Одна картинка со всеми концептами для показа человеку |
| `presentation_board.py <spec.json>` | Презентация с макетами под отрасль; образец спецификации `templates/presentation-spec.example.json`; `--png-dir` даёт PNG слайдов, `--list-mockups` список макетов |
| `render_png.py <файлы.svg> --size 512` | SVG в PNG с прозрачностью; `--ico favicon.ico` собирает фавикон; `--which` показывает доступные рендереры |
| `export_variants.py <знак.svg> --web-icons` | Чёрная, белая, одноцветная, квадратная версии, фавикон и значок приложения; `--png` размеры; `--web-icons` ещё и набор иконок с манифестом и строками для `<head>` |

У каждого скрипта есть `--help`. Результаты идут в `$WORK/<проект>/out/`, если не задан `-o` или `--out-dir`; исходный знак человека не меняется.

## Ограничения

- Юридическую уникальность знака модуль не гарантирует: скажи человеку, что нужен поиск по базам товарных знаков.
- Шрифты в знаке должны быть переведены в контуры; лицензия шрифта должна разрешать использование в знаке.
- Чужие знаки используй только как материал для сравнения и учёбы, не копируй и не обводи.
- Не заявляй проверок, которые не запускал (например, если рендерера нет, скажи об этом).
- Строки «PNG export skipped» и «web icons skipped» при успешном завершении значат неполный комплект: сверяй сами файлы. Значок 16 и 32 px проверяй тем рендерером, где он будет жить (браузер, система), разные рендереры показывают его по-разному.
- В брифе название записывается точно: регистр, буквы «ё» и «й». Русские буквы не подменять похожими латинскими.
- Для движения знака в ролике (раскрытие, заставка) перейди к навыку `cadence-structures` (структура liquid-mark).
