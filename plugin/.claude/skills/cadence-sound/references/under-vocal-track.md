# Эффекты под треком с голосом

Случай: трек с вокалом или речью поверх музыки, на нём щелчки интерфейса, клавиши, whoosh. Эффекты должны быть слышны, но оставаться под треком. Инструменты — три скрипта в `skills/cadence-sound/scripts/`: `cue_mix.py` (собрать дорожку эффектов), `level_check.py` (проверить уровни), `sfx_probe.py` (паспорт файла).

## 1. Какой кусок трека брать

Трек длиннее ролика — окно выбирается по словам, а не по громкости.

1. Слова трека с временем: `python3 scripts/captions_whisper.py <трек>` пишет `<имя>.words.json` (Whisper работает локально; если он не установлен, скрипт скажет, как поставить).
2. Лучшее окно — где **конец трека совпадает с концом ролика**: финал не обрывается на полуслове, а при повторе ролик начинается с начала фразы.
3. Сверить фразы с действием в кадре. Слово, которое по смыслу совпало с действием («готово» — на появлении готового результата), читается как задуманное.
4. Начало окна — в паузе между фразами. Вход трека — затухание 0,2 с (`fadeIn`), выход — 0,3 с после последнего слова (`fadeOut`).
5. Время окна (`bed.from` в `cues.json`) держать в одном месте с таймингом картинки, чтобы звук и кадр не разъехались после правки.

## 2. Карта событий и сборка

`cues.json` лежит в папке проекта, рядом с треком:

```json
{"duration": 15.5,
 "bed": {"file": "in/track.mp3", "from": 42.0, "fadeIn": 0.2, "fadeOut": 0.3, "window": 1.0},
 "cues": [
  {"id": "fly",  "event": 4.62, "file": "whoosh.wav", "anchor": "peak",  "rel": -14},
  {"id": "tap",  "event": 6.10, "file": "tick.wav",   "anchor": "onset", "rel": -15},
  {"id": "keys", "event": 8.00, "file": "key-1.wav",  "anchor": "onset", "rel": -20}
 ]}
```

```bash
python3 skills/cadence-sound/scripts/cue_mix.py "$WORK"/<проект>/cues.json \
  --out "$WORK"/<проект>/out/sound --library sounds
```

- `--library` — папка с эффектами, от неё считаются пути `file` (здесь `sounds/` поставки; своя папка человека — его путь). Без флага пути считаются от папки `cues.json`.
- `anchor`: `onset` — удар, щелчок, клавиша; `peak` — whoosh, нарастание. Точки меряются так же, как `sound_anchor.py`, и совпадают с `sounds/sounds.json`.
- `hp` — срез низа, по умолчанию 80 Гц; `fade` — затухание к концу файла.
- Подводка, которая начинается раньше нуля, обрезается — `placements.json` покажет `cutHead`.

## 3. Уровни эффектов относительно трека

`rel` — на сколько дБ эффект тише трека: самое громкое окно эффекта (до 200 мс) против трека в окне 1 с вокруг него.

| Роль | `rel` |
|---|---|
| акцент: вылет, главный переход | −14 дБ |
| живой звук: щелчок, переключатель, перелёт | −15 дБ |
| фон: клавиши, тики счётчика, рамки | −20 дБ |

- **Окно трека — 1 с.** В треке с голосом короткое окно попадает то в слог, то в паузу между словами, и одинаковые щелчки подряд расходятся на 20 дБ. Секунда меряет громкость фразы.
- Пик одного клипа — не выше −6 dBFS.
- **Лимитера нет.** Если трек с эффектами громче −1,5 dBFS по отсчётам, всё опускается одной поправкой: трек и эффекты вместе, соотношение сохраняется. Запас 0,5 дБ к −1 нужен на межотсчётные пики.
- Эти уровни — и для трека без голоса: правило «музыка главная» одно на все ролики. Если на телефоне эффект не слышно, поднимать по 1–2 дБ и проверять скриптом.

## 4. Проверка числом

```bash
python3 skills/cadence-sound/scripts/level_check.py --mix "$WORK"/<проект>/out/sound/mix.wav \
  --sfx "$WORK"/<проект>/out/sound/sfx.wav --placements "$WORK"/<проект>/out/sound/placements.json
```

| Что показал | Значит |
|---|---|
| эффект громче −10 дБ к треку | FAIL: эффект над музыкой |
| от −12,5 до −10 дБ | предупреждение: на грани |
| тише −30 дБ | предупреждение: под треком не слышно |
| эффекты подняли микс больше чем на 1,5 LUFS | FAIL: эффекты над музыкой |

Хороший микс: эффекты почти не добавляют громкости (десятые доли LUFS), самый громкий — около −14. Код выхода 1 при FAIL. Для отдельной дорожки музыки — `--music <файл>` вместо `--mix`.

## 5. Тональность

Чужой трек — тональность неизвестна, и эффект с высотой нот может прозвучать фальшиво.

```bash
python3 skills/cadence-sound/scripts/sfx_probe.py --library sounds whoosh.wav bell.wav
```

Плоскостность спектра меньше 0,1 — звук тональный, скрипт пометит его. Под чужой трек брать шумовые эффекты (whoosh из шума — около 0,3). Очень короткие щелчки и клавиши (до 0,1 с, как `tick.wav` и `key-*.wav`) тоже выходят «тональными» по числу, но на слух высоты не имеют — их можно оставить. Ещё скрипт показывает долю энергии ниже 60 Гц: большая доля перегружает динамик телефона, такой звук срезать по низу.

## 6. Whoosh — только на настоящем перелёте

Кадр уезжает, карточки вылетают, сцены встают в ряд — да. Жёсткая склейка без движения — нет: звук подлёта без подлёта звучит неуклюже.

## 7. Два файла на выходе

- `mix.wav` — трек и эффекты: для черновика и для ролика, в который трек вшивается.
- `sfx.wav` — одни эффекты с теми же уровнями: если трек добавляется в приложении площадки из её библиотеки. Ролик собирается с `sfx.wav`, а трек на площадке ставится с того же места (`bed.from`). Площадка может распознать чужой трек, вшитый в файл, и заглушить ролик — поэтому для публикации чужой музыки этот вариант надёжнее.
