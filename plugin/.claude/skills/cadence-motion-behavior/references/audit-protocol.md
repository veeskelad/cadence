# Поиск движения, аудит и исполнимое исправление

## Три режима

Выбор при идее ищет только полезные связи; ревью оценивает выбранную реализацию; аудит изучает все затронутые места и общие корневые причины. Они используют один канон движения, но выдают разные результаты. Не вводить обязательную остановку между ними, если исправление уже поручено.

## Карта проверки

Записать renderer/платформу, версии из проекта, текущие токены, owners transform/clip, источник clock и материалы. Обследовать: причины и реакции; ориентацию и непрерывность; чтение; кривые/массу; повтор и прерывание; вычислительную стоимость; доступность; согласованность пака. Для UI дополнительно частоту операций и события ввода; для MP4 порядок seek и готовность ресурсов.

Возможность движения подтверждается существующим разрывом: новое состояние теряет источник, порядок непонятен, результат не выделен, объект телепортируется. Рядом записать место, текущее поведение, предлагаемую связь и причину. Кандидат без выигрыша понимания/выразительности отбрасывается; не создавать длинный список пожеланий ради полноты.

## Доказательство дефекта

```text
Место и версия: точный путь/строка или событие
Наблюдение: что видно и при каких входах
Причина: подтверждённая / гипотеза
Нарушенный контракт: clock, чтение, anchor, continuity, state, performance
Последствие: неверные данные / потеря понимания / затраты / качество
Исправление: минимальное изменение и существующие токены
Проверка: конкретное входное состояние и наблюдаемый результат
Уровень подтверждения: код / preview / итоговый MP4 / устройство
```

Не считать специально выбранный tradeoff дефектом без проверки сценария. Повторяющиеся симптомы общего неверного clock объединить в одно исправление. Приоритет: ошибочные данные и недетерминированность → причинность/читаемость → continuity → подтверждённая стоимость → декоративная настройка.

## План, который исполняется без истории чата

```text
ID и статус; базовая revision
Проблема: вход/событие, текущее поведение и точное место
Цель: конечные состояния, значения после разрешения токенов
Контракт: bounds, anchor, owners, clock, before/after
Шаги: конкретная правка каждого затронутого места
Границы: материал человека, public release и несвязанные файлы
Проверки: команды установленного проекта, события и критерии
Риски: что пока только предположено
Результат: что действительно проверено и что осталось
```

Если revision изменилась, перечитать затронутое и адаптировать план к действующему коду; не выполнять устаревшую строку механически. Не требовать отдельного дизайн-согласования уже порученной обратимой правки. Решение выбора взаимоисключающих концепций остаётся человеку, когда оно не задано запросом.

## Ревью

Представить только подтверждённые проблемы: место · наблюдение · исправление · проверка. Удаление лишнего действия предпочтительнее усложнения. Просмотреть обычный темп для смысла, соседние кадры для непрерывности, разные порядки seek для чистоты state. В UI проверить повторный ввод, cancel и системные предпочтения; на мобильном — реальные устройства, когда они доступны. Не выдавать кодовое ревью за просмотр MP4 или проверку физического устройства. Итог явно различает выполненную проверку, предположение и блокирующую причину.
