# От визуального решения к реализации

Прочитать [процедуру переноса](references/build.md). Вход: разрешённый материал, текущий проект/renderer, точный текст, утверждённый пак, требуемая функциональность и формат. Изображение может быть собственным скриншотом, эскизом, принятой генерацией или разрешённым образцом. Генерация нового изображения не обязательна.

Выход — реальная реализация в текущем стеке и проверка требуемого результата. Изображение другого продукта не разрешает копирование его бренда или уникальных assets. Для собственного дизайна сохранять существенные отношения точно. Для вдохновения воспроизводить принцип своими материалами.

Не менять стек и публичный DESIGN ради удобства; зависимости проверить в текущем проекте. Новый внешний вызов/скачивание остаётся отдельным действием. Для MP4 использовать один seek clock, motion-behavior и контракт текущего renderer. Для web/app интерактивной реализации использовать назначенный навык интерфейсов; правила видео не доказывают доступность приложения.

Граница и приоритеты — совместимость внутренних модулей (`knowledge/system/compatibility.md`, от корня выпуска). Дополнительные layout/material/behavior поля хранить в спецификации сцены, не расширять pack.json: актуальные поля и валидатор определяет cadence-style.
