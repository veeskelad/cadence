# Автоматический монтаж: инструменты и практики

Разведка 16.09.2026 по четырём направлениям: сборка чернового монтажа, субтитры, ритм и вставки, существующие продукты. Задача — понять, из чего собирается локальный монтаж разной сложности, субтитры и вставки, без облака. Ссылки проверены на дату разбора; где источник косвенный, это помечено.

## 1. Как отдавать собранный монтаж в Resolve

| Инструмент | Что делает | Ограничение |
| --- | --- | --- |
| [OpenTimelineIO](https://github.com/AcademySoftwareFoundation/OpenTimelineIO) | модель таймлайна и конвертеры; v0.18.1, ноябрь 2025, живой проект ASWF | с v0.16 адаптеры вынесены в отдельный пакет `OpenTimelineIO-Plugins`, часть из них полузаброшена; [EDL-адаптер](https://github.com/OpenTimelineIO/otio-cmx3600-adapter/releases) стоит на v1.0.0 с 2023 года |
| [auto-editor](https://github.com/WyattBlue/auto-editor) | режет тишину и статику, экспортирует таймлайн: `--export resolve\|premiere\|final-cut-pro\|kdenlive` | порог в dB: на шумной записи срезает глухие согласные и тихие концы фраз, лечится `--margin` |
| [PySceneDetect](https://www.scenedetect.com) | детекция склеек и планов, v0.7.1, июль 2026 | F1 меньше 0,6 на плавных переходах; резкие склейки ловит уверенно |
| [pycmx](https://github.com/iluvcapra/pycmx) | разбор EDL CMX 3600 | только чтение |
| [otio-kit](https://github.com/Egnatia-OC/otio-kit) | собирает OTIO из монтажного брифа | AGPL; проверен автором на бесплатном Resolve 21.1 |

**Форматы обмена.** DRT — родной, но закрытый: получить его можно только из самого Resolve. OTIO импортируется с версии 18.5, но есть воспроизводимые баги с порядком дорожек ([KDE bug 503692](https://www.mail-archive.com/kde-bugs-dist@kde.org/msg1051588.html)). FCPXML переносит несколько дорожек, трансформации и простые кроссдиссолвы, но теряет маркеры. EDL самый предсказуемый и самый бедный: одна видеодорожка, все переходы становятся Cross Dissolve.

**AI-инструменты Resolve, которые скриптуются:** `Timeline.DetectSceneCuts()`, `TimelineItem.SmartReframe()`, `MediaPoolItem.TranscribeAudio()` и `GetTranscription()`, `Timeline.CreateSubtitlesFromAudio()`, `CreateMulticamClip()`, `PerformMulticamSmartSwitch()`, `GenerateSpeech()`. Не скриптуются IntelliScript, Music Editor и сам интерфейс Text-Based Editing — но `GetTranscription()` отдаёт слова с таймкодами, и монтаж по тексту можно собрать самому.

**Про Studio.** В Resolve 21.1 от 08.09.2026 Python API стал функцией Studio ([обзор CineD](https://www.cined.com/davinci-resolve-21-1-released-ai-assistant-integration-via-mcp-individual-hdr-trims-and-python-scripting-moves-to-studio/)), там же появился встроенный MCP-сервер. Проверено 16.09.2026 на одной машине: `resolve.GetProductName()` вернул «DaVinci Resolve Studio», версия 21.1.0.14 — скриптовый путь, транскрипция, Smart Reframe и MCP доступны. Для инструментов, которые уйдут другим людям, ограничение всё равно учитывать: на бесплатной версии останется только файловый обмен.

## 2. Субтитры на русском

| Инструмент | Что делает | Ограничение |
| --- | --- | --- |
| [GigaAM v3](https://github.com/salute-developers/GigaAM) | открытый русский ASR, MIT, пословные тайминги штатно, длинные записи через VAD | поддержка Apple Silicon в репозитории не заявлена; бенчмарки сняты на коротких фразах, не на речи в кадре |
| [whisper.cpp](https://github.com/ggml-org/whisper.cpp) | Metal и Core ML на Apple Silicon, large-v3 примерно 2–3× реального времени | пословные тайминги — эвристика поверх attention, на русском грубее |
| [WhisperX](https://github.com/m-bain/whisperX) | forced alignment, точность границ слова лучше 100 мс | русская модель выравнивания слабее английской, на Mac всё считает CPU |
| [AutoSubs](https://github.com/tmoroney/auto-subs) | MIT, локально, ставит в таймлайн Resolve стилизованные Text+ с пословной подсветкой, умеет GigaAM v3 | веса MMS для выравнивания под CC BY-NC — для коммерции не годятся; версия Resolve из App Store не поддерживается |
| [stable-ts](https://github.com/jianfch/stable-ts), [pysubs2](https://github.com/tkarabela/pysubs2) | устойчивые тайминги и запись ASS с тегами караоке | формат и постобработка, распознавание не улучшают |

**Что в самом Resolve.** Транскрипция и «Voice to Subtitle» — только Studio. В бесплатной версии есть субтитровый трек, импорт и экспорт SRT, ручная правка; пословных таймингов нет. Конвертеры Text+ опираются на недокументированное поведение API — [автор Resolve-OpenCaptions предупреждает об этом прямо](https://github.com/david-ca6/Resolve-OpenCaptions).

**Читаемость в вертикальном кадре 1080×1920** (сводка по [Blitzcut](https://blitzcutai.com/blog/best-caption-placement-short-form-video) и [Kreatli](https://kreatli.com/guides/safe-zone-guide), это практика площадок, а не измерение):

- безопасный прямоугольник 900×1400 по центру; у Reels нижняя мёртвая зона 310–450 px;
- блок текста по Y примерно 1200–1550 px — выше интерфейса, но не на лице;
- кегль 60–75 px при жирности 700–900; караоке требует 65–80 px;
- не больше двух строк в блоке; караоке — 1–3 слова на экране, фраза целиком — 3–8 слов.

## 3. Ритм и вставки

- **Доли музыки:** [beat_this](https://github.com/CPJKU/beat_this) (MIT, beat и downbeat одной моделью) или `librosa.beat_track` для ровной электроники. [madmom](https://github.com/CPJKU/madmom) точнее на живой музыке, но **веса под CC BY-NC** — в коммерческой работе не использовать. aubio и Essentia отпадают по GPL/AGPL.
- **Сборка по речи:** auto-editor с запасом `--margin`, [Silero VAD](https://github.com/snakers4/silero-vad) (MIT) вместо порога громкости на шумных записях, пословные тайминги — для реза по фразе, а не по тишине.
- **Поиск вставки в своей медиатеке:** эмбеддинги кадров ([SigLIP 2](https://huggingface.co/docs/transformers/model_doc/siglip2) или CLIP) в [sqlite-vec](https://github.com/asg017/sqlite-vec) — одна база в файле, без сервера. Видеоэнкодеры с временной структурой тяжелее и для вставок в 1–3 секунды выигрыша не дают.
- **Разбор исходников на планы:** PySceneDetect для резких склеек, [TransNetV2](https://github.com/soCzech/TransNetV2) и [AutoShot](https://github.com/wentaozhu/AutoShot) точнее (F1 0,75–0,82), но чекпоинты старые и на Apple Silicon заводятся руками. Крупность дёшево оценивается долей бокса лица в кадре.
- **Длина плана.** Открытых данных об удержании нет: цифры «1,5–3 с на склейку» гуляют по SEO-блогам без методики. Единственный честный источник — собственная аналитика опубликованных роликов. Для ориентира по ритму сцены есть база средней длины плана в кино [Cinemetrics](http://www.cinemetrics.lv).

## 4. Что уже делают продукты и где у них брак

Opus Clip, Vizard, Submagic, Captions, Descript, AutoPod, AutoCut, Eddie AI и их клоны делают один и тот же набор: выбор фрагмента по транскрипту, пословные субтитры с подсветкой, рефрейм по активному говорящему, подбор стока по ключевым словам.

Повторяющиеся жалобы 2025–2026: 20–40 % клипов в брак из-за неполного по смыслу фрагмента; субтитры приходится перевыравнивать после ручных склеек; B-roll подбирается по словам, а не по смыслу, и его переделывают почти всегда; оценка «виральности» противоречива — это сортировка, а не прогноз.

Экспорт в NLE есть у немногих: Descript отдаёт XML (теряя титры, переходы, эффекты и скорость), Opus Clip — XML плюс SRT и исходные сегменты с запасом 30 секунд, Eddie AI работает расширением внутри Resolve. Остальные отдают только MP4.

## Выводы для автоматического монтажа

1. **Отдавать таймлайн, а не только рендер.** Правка склеек и субтитров остаётся у человека — ровно там, где у всех продуктов брак. Основной канал — FCPXML, запасной — EDL; оба работают без Studio. OTIO удобен как внутренняя модель, но не как единственный мост.
2. **Три функции дают больше всего пользы:** пословные субтитры с подсветкой, сглаженный рефрейм по активному говорящему, выбор самодостаточного фрагмента по транскрипту. Первые две целиком локальны.
3. **Русская речь:** GigaAM v3 как основной распознаватель, whisper.cpp через Metal как запасной. Караоке собирать в ASS с тегами `\k`, а не через конвертеры Text+ на недокументированном API.
4. **Вставки:** готового открытого подборщика «фраза → нужный кадр» нет. Связка «транскрипт с таймкодами → топ-N кадров из своей медиатеки по эмбеддингам» пишется самостоятельно.
5. **Приёмы — из словаря:** [424 приёма](../techniques/README.md) — для постановки задачи и проверки результата, включая колонку с инструментом Resolve.

Нарезка пауз, субтитры и синхронизация звука на живом видео в Cadence — [cadence-cut](../../skills/cadence-cut/SKILL.md); передача в Resolve — [cadence-resolve](../../skills/cadence-resolve/SKILL.md). Установка любого инструмента из таблиц выше — только с согласия человека; лицензии проверять до использования в коммерческой работе.
