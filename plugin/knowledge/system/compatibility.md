# Совместимость модулей Cadence

Пути от корня выпуска Cadence. Эти правила применяются совместно с профильным навыком и разрешают пересечения общей системы. Дополнительные модули уточняют решение задачи; они не запускают все режимы сразу.

## Кто отвечает за действие

Первый запрос и выбор ближайшего результата — skills/cadence. Сборка и MP4 — skills/cadence-motion, ритм — cadence-beat-reel, структура — cadence-structures, свой пак — cadence-style, генерационный brief — cadence-generate, звук — cadence-sound, живое видео — cadence-cut, Resolve — cadence-resolve. Дополнительные навыки уточняют смысл, вид, поведение и проверку. Их наличие не заменяет главный маршрут и не означает разрешение на новый продукт, сервер, сервис или установку.

Внутри общей задачи не начинать знакомство заново и не предлагать стартовое меню. При выборе нескольких вариантов не запускать процедуру prototype без потребности сравнения. Работа над роликом не требует web/mobile/Swift модуля: он используется для изображения поведения реального интерфейса либо явно заказанной разработки интерфейса.

## Приоритет и область правил

1. Прямой запрос и реальные ограничения результата, разрешения на действия и фактические материалы.
2. Технические инварианты: единый clock для MP4, неизменные входы, права на материалы, локальные ресурсы, граница публикации.
3. Утверждённый пак и специфичные правила выбранного типа результата.
4. Частные рецепты и эвристики.

Разрешать противоречие по области: UI transition описывает взаимодействие, beat-sting короткий акцент, hold читаемого тезиса объяснение. Одно числовое значение из чужой области не ограничивает остальные. Не менять пак автоматически: если намерение требует иного токена, использовать допустимую настройку сцены или отдельную задачу изменения пака.

## Известные пересечения

| Пересечение | Решение в Cadence |
|---|---|
| design/DESIGN.md требует готовое состояние не дольше 0,5 с; motion-laws.md требует чтение | 0,5 с — ориентир декоративного ритмического акцента. У читаемой фразы hold определяется фактическим чтением после посадки последнего слова. Доли музыки не сокращают чтение. |
| Старые поля 190/320/64 против рабочей области площадки | Для Reels/TikTok существенное внутри пересечения пака с x=0.06W…0.82W/y=0.15H…0.75H; проверка реального UI и cover crops уточняет область. Старые поля не доказывают безопасность. |
| cadence-style требует отдельный demo перед паком | В работе оценивать пак на нужных сценах текущего результата. Отдельный demo только если нужен задаче; его длина не является обязательным этапом. Валидация schema сохраняется. |
| motion-laws каскад с сокращающимися задержками против равномерного stagger | Для обычного текстового каскада канон motion-laws. Равномерный stagger — только если надо показать равномерные шаги/синхронность данных. Не выдавать оба как default одного сценария. |
| word-reveal blur/opacity против моментального появления слов | Канонический текст виден с начала события, без fade/blur; мягкий reveal явно выбирается как иной совместимый режим. |
| UI cubic/ease-out на уходе против стыка по инерции | У обычного MP4 стыка общий track: выход разгоняется до реза, вход тормозит после; цель движения/скорость согласованы. Симметрия UI не заменяет этот закон. |
| Пружины и material blur против запрета резинки/расфокуса текста | Пружина — реакция массы с ограниченным перелётом, текст стабилен на hold. Background/material blur отделён от текста; motion blur подкадровый. |
| Случайный дизайн против воспроизводимого render | Варианты можно выбрать до сборки; сохранить seed и решения. Каждый t воспроизводится независимо от истории. Непосеянная random на кадре запрещена. |
| Image-first workflows против cadence-generate | Образец/brief можно подготовить локально из своих входов. Генерация в сервисе человека через существующий маршрут; не требовать конкретного внешнего инструмента или отправки материалов. |
| Live gestures, hover, toasts, scroll против video clock | В интерактивном приложении реальные события; в MP4 журнал событий и чистая функция t. Не переносить wall-clock timers, RAF накопление и пользовательский input в экспорт. |
| Frontend/native зависимости против установленного engine | Сначала текущий стек. Рекомендация не установка. Новая зависимость проверяется на совместимость и лицензию, применяется только в разрешённой задаче. |
| Mandatory redesign/font bans против бренд-пака | Сохранять утверждённые цвета/шрифты. Другие направления возможны по запросу; материальный скриншот не перекрашивать. |
| Полнота output против раскрытия внутреннего рассуждения и длинных ответов | Полнота относится к файлам/требованиям, ответ содержит результат и проверяемое основание. Не раскрывать внутреннюю цепочку рассуждений, не раздувать пользовательский интерфейс. |
| Research-проценты и magic prompts против достоверности | Непроверенные численные утверждения и причинные гипотезы не становятся законами. Использовать наблюдаемые критерии полноты и тесты. |

## Граница


Память preferences читается, если доступна в выбранной рабочей папке. Её отсутствие не блокирует текущую задачу. Уже явное разрешение на работу не требует повторного общего согласования; необратимое действие или новая внешняя операция за его пределами сохраняет отдельное разрешение.

Пак валидируется skills/cadence-style/scripts/validate_pack.py: верхние поля не расширяются произвольно; typography имеет display/body/mono, motion задаёт character. Role impact из старого DESIGN — решение сценического текста, а не дополнительное поле typography. Новые направления, кривые, свет, material и layout сохранять в спецификации сцены/дизайн-контракте отдельно от pack.json. Кривые из текущего renderer сохраняются, когда соответствуют задаче; cubicOut из карточки — явно выбранный вариант, не автоматическая замена default expoOut. Safe area берётся из design/tokens.json и ужесточается областью площадки; не предполагать наличие safe в pack schema.

Поиск публичной официальной документации по конкретной ошибке допустим. Запрос найти актуальные палитры разрешает чтение соответствующих источников; фиксировать ссылки и дату. Это не разрешает отправку материалов, скачивание/обновление зависимости, вызов сервиса или выполнение upstream scripts. Запрет провайдерных CLI сохраняет приоритет над отдельным старым рецептом отделения фона. Resolve работает только с копией и разрешённой правкой; длина необходимой проверки выбирается задачей, а не обязательным пробным интервалом.

При t<start всегда вернуть from; при duration=0 и t≥start вернуть to. Нулевой интервал не раскрывает будущее событие заранее.

Экспорт видео проходит текущие npm scripts, проверки кадров и громкости существующего процесса. Для Reels/TikTok по умолчанию 1080×1920, квадратные пиксели; проверить dimensions, SAR/DAR и rotation файла, UI-overlay и обложку. Наличие инструкции не подтверждает готовый рендер.
