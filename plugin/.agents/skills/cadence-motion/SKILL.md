# Моушн кодом

**Где запускать команды.** Корень Cadence: `${CLAUDE_PLUGIN_ROOT}`. Если выше стоит путь к папке — Cadence стоит плагином: команды этого навыка запускать из этой папки (`cd` туда), свои файлы человека — в `$WORK`, не в ней. Если видна сама запись в фигурных скобках — это папка выпуска или исходников, команды запускаются из неё.

Ролик здесь — это HTML-страница, которую движок `engine/` (HyperFrames) покадрово снимает в MP4. Всё рисует код: three.js, WebGL-шейдеры, canvas. Ключи, сеть и платные сервисы не нужны.

Соседи: живое видео (нарезка, субтитры) — `cadence-cut`; DaVinci Resolve — `cadence-resolve`; любой звук — `cadence-sound`; цвета и шрифты — `cadence-style`.

## Где лежат файлы

| Что | Где |
|---|---|
| Шаблоны роликов | `engine/templates/<id>/`: `index.html`, у шаблонов со звуком ещё `cues.json` (события звука); живое видео из `film.videos` сборщик ставит на метку `<!-- cadence:videos -->` |
| Общий код | `engine/lib/motion.js` — кривые, пружины `spring`/`springTrack`, сид `rng`, `beatTime`, `bindSeek`; `engine/lib/shots.js` — 21 генератор кадров `shot*`, 8 тонов `TONES` и `withTone`, глиф-шум для расшифровки текста `glyph`; `engine/lib/timing-kit.js` — набор текста, нормы чтения `readSec`/`assertReadable`, сетка долей; `engine/lib/phone.js` — телефон в реальных пропорциях |
| Сборщик | `node engine/build.mjs <шаблон> --film <film.json> [--pack <id>] [--format WxH] [--set ключ=значение] --out <папка сборки>` |
| Огибающая бочки | считает сам сборщик из трека и кладёт в сценарий: `film.reel.kick` (16 значений на долю) |
| Пример сценария | `examples/beat-reel/film.json` |
| Структура трека | `python3 scripts/track_structure.py <трек>` |
| Время графики по словам речи | `python3 scripts/word_anchors.py --words <слова> --film <film.json> --out <film.resolved.json>` |
| Проверки готового MP4 | `scripts/check_reel.py` (с `--flashes` — вспышки на кадр), `scripts/frame_flashes.py`, `scripts/safe_zone_check.py` (зоны и обложка) |
| Демо-трек, если своего нет | `python3 scripts/demo_beat.py --out "$WORK"/<проект>/in/demo-beat.wav` — синтезирован кодом, лицензия не нужна |
| Звуки | `sounds/*.wav`, их начало и пик — `sounds/sounds.json` (см. `cadence-sound`) |
| Стиль | свой пак — `$WORK/packs/<id>/pack.json`, встроенные — `design/packs/<id>/`, по умолчанию `cadence-ember` |
| Работы человека | `$WORK/<проект>/`: `in/`, `build/`, `out/` (путь — ниже) |

**Рабочая папка `$WORK`.** Если задана переменная `CADENCE_WORK` — она. Иначе в установленном выпуске (`…/releases/<id>/`) — `../../work` от корня выпуска, в dev-репозитории — `./work`. Все команды ниже запускаются из корня выпуска, а `$WORK` задаётся так:

```bash
WORK="${CADENCE_WORK:-$( [ "$(basename "$(dirname "$PWD")")" = releases ] && echo "$(cd ../.. && pwd)/work" || echo "$PWD/work" )}"
```

Исходники человека не меняются: результат всегда новый файл в `$WORK/<проект>/out/`.

Не нашли подходящий — скажите это человеку и предложите ближайший шаблон. Нужна съёмка или эффект на живом видео — это `cadence-resolve` или `cadence-cut`. Ролик о своём продукте на его экранах — [references/product-video.md](references/product-video.md).

## Порядок работы

1. **Идея одной фразой.** Что зритель поймёт к концу. Согласовать с человеком до кода.

   Если на входе тема, а не готовый сценарий: разбить идею на 3–8 смысловых долей, в каждой одна главная мысль. Для каждой доли выбрать шаблон или кадр из `shots.js` и записать, что ей нужно: ничего (рисуем кодом), точный факт с источником или материал человека. Материала нет — так и сказать, не подделывать. Текст на экране — в пределах: заголовок до 5 слов и 28 знаков, текст до 90 знаков, хук `beat-reel` — до 16 знаков (`design/tokens.json` → `type`). Текст в пределах помещается в раскладку; не помещается — сократить, а не уменьшать шрифт.
2. **Движок на месте?** `python3 scripts/engine_setup.py status`: `ready` — идём дальше; `cached` — `install` подключит его без сети; `missing` — спросить: «Скачать зависимости движка (~300 МБ) из npm?» Только после согласия: `python3 scripts/engine_setup.py install`. Это сеть, один раз на компьютер: следующие версии Cadence с теми же зависимостями подключат его без скачивания.
3. **Трек → сетка долей** (если есть музыка; своего трека нет — `scripts/demo_beat.py`):
   ```bash
   python3 scripts/track_structure.py "$WORK"/<проект>/in/track.mp3 --hook-beats 3 --json "$WORK"/<проект>/track.json
   ```
   Скрипт печатает темп, первую долю, дроп, брейки и точку входа ролика. Все времена дальше пишутся в долях: `доля n = n × 60 / BPM` секунд (`beatTime` в `motion.js`). Для `beat-reel` сборщик делает этот разбор сам: ролик входит в трек так, чтобы хук закончился ровно на дропе.
4. **Сценарий.** Скопировать `examples/beat-reel/film.json` в `$WORK/<проект>/film.json` и заполнить словами человека: `music` (файл и громкость), `trackTitle`, `hook` (строка, акцент, подпись), `mark` (имя, слоган, призыв). Путь к музыке — относительно файла сценария. У остальных шаблонов параметры — атрибуты `data-*` на корне `index.html`, их меняет `--set ключ=значение`.
5. **Сборка:**
   ```bash
   node engine/build.mjs beat-reel --film "$WORK"/<проект>/film.json --pack cadence-ember --out "$WORK"/<проект>/build
   ```
   `--format 1920x1080` — горизонтальный кадр, по умолчанию 1080×1920. Сборщик копирует в папку сборки код, шрифты, звуки и файлы сценария: рендер не видит путей выше своей папки.
6. **Проверка сборки.** Путь к папке — абсолютный: npm запускает скрипт из `engine/`.
   ```bash
   npm --prefix engine run check -- "$WORK/<проект>/build"
   npm --prefix engine run snapshot -- "$WORK/<проект>/build" --at 1,4,7
   ```
   Скрипт `snapshot` движка уже добавляет `--describe false`. Если HyperFrames когда-то вызывается в обход скриптов — флаг обязателен: без него кадры могут уйти на описание во внешний сервис.

   **Стилфрейм до рендера.** Новый вид, а не готовый шаблон с уже принятым паком: снять 1–3 ключевых кадра через `snapshot` и показать человеку до полного рендера. Спросить одно: «Такой кадр нужен?». Правки вида вносить в сцену, а не в готовый ролик. Для шаблона с принятым паком этот шаг не нужен.
7. **Рендер:**
   ```bash
   npm --prefix engine run render -- "$WORK/<проект>/build" --quality high --fps 30 --output "$WORK/<проект>/out/<имя>.mp4"
   ```
   `--quality high` обязателен: в обычном качестве тонкие линии и мелкий текст мылятся.
   Камера растягивает фото или видео больше чем в 1,2×: рендерить с `--resolution portrait-4k` и уменьшать: `ffmpeg -i raw.mp4 -vf "scale=1080:1920:flags=lanczos" -c:v libx264 -crf 13 -c:a copy out.mp4`. Для обычных сцен не нужно: рендер заметно дольше.
8. **Проверка MP4 по кадрам** — раздел ниже. Без неё ролик не готов.
9. **Звук** — по `cadence-sound`: карта событий, пик звука на событие, итог около −14 LUFS.
10. **Два проверяющих** — свой просмотр и второй агент, которому не рассказывали, как ролик собирали: [references/final-review.md](references/final-review.md). Круг «исправить → отрендерить → проверить весь ролик» — пока у обоих нет замечаний.
11. **Обложка — к каждому ролику, без просьбы.** 2–3 кадра самого ролика без подписей и призыва, на них один короткий заголовок шрифтом пака — там, где в ролике живёт текст. Всё важное — в центральной обрезке 3:4: так обложку показывает сетка профиля (у 1080×1920 это y 240–1680). Кандидаты и лист сравнения: `python3 scripts/safe_zone_check.py cover <ролик.mp4> --at <с>,<с>,<с> --out "$WORK"/<проект>/check/cover`. Заголовок ставить в сцене (`snapshot` нужного момента), а не дорисовывать поверх MP4. Выбранную сохранить как `$WORK/<проект>/out/cover.jpg` и проверить `safe_zone_check.py check …/cover.jpg`; остальные кандидаты и лист удалить. Генерация картинки для обложки — только по прямой просьбе.
12. **Показать человеку** готовый файл: `open "$WORK"/<проект>/out/<имя>.mp4`. Спросить одно: принять, поправить или отказаться. Промежуточные снимки удалить.

## Проверка рендера по кадрам

`snapshot` снимает страницу, но **не перематывает видео внутри неё**. Он годится для 3D, текста и вёрстки. Всё, где есть видео, проверяется только по кадрам из готового MP4.

```bash
# техпроверка одной командой: формат, громкость, пик, чёрные и замершие куски, вспышки на кадр
python3 scripts/check_reel.py out.mp4 --flashes
# текст в безопасных зонах (на macOS строки находит OCR; иначе — смотреть лист с рамками)
python3 scripts/safe_zone_check.py check out.mp4 --overlay "$WORK"/<проект>/check/zones
# факты файла: размер, fps, длительность, звук
ffprobe -v error -show_entries stream=codec_type,width,height,r_frame_rate:format=duration -of compact out.mp4
# контакт-лист: 2 кадра в секунду, 6 в ряд
mkdir -p "$WORK"/<проект>/check
ffmpeg -v error -i out.mp4 -vf "fps=2,scale=270:-1,tile=6x6" -frames:v 1 -y "$WORK"/<проект>/check/sheet.png
# кадр на стыке (секунды)
ffmpeg -v error -ss 4.60 -i out.mp4 -frames:v 1 -y "$WORK"/<проект>/check/t4.60.png
# громкость и пик
ffmpeg -i out.mp4 -af ebur128=peak=true -f null - 2>&1 | tail -12
```

Глазами проверить:
- первый кадр уже движется, последний — не чёрный и не пустой;
- текст читается целиком, не вылез за безопасные поля (у 9:16 сверху 190 px, по бокам 64 px, снизу 320 px — `design/tokens.json` → `safe.vertical`, проверка — `scripts/safe_zone_check.py`);
- смены кадра стоят на ударах: кадры за 1–2 до и после каждого удара;
- на каждом стыке нет белой вспышки, пустого кадра и «прыжка» камеры (`--flashes` ловит вспышки и пропадания на один кадр; задуманную вспышку указать в `--allow`);
- у сцены с отдельными событиями проверить в итоговом MP4 кадр сразу после завершения действия и соседние кадры у сомнительного стыка; участок просмотреть в обычном темпе, после исправления — на новом MP4;
- только у зацикленного ролика сравнить последние два кадра с первыми двумя: на шве должны сохраняться положение, направление и скорость движения, а не только похожий стоп-кадр;
- видео-экраны играют, а не стоят на одном кадре;
- цвет исходников человека совпадает с оригиналом.

Технический PASS — это не решение человека. Решение «нравится или нет» и «публикуем или нет» принимает он.

## Как не выглядеть шаблоном

- **Смена кадра — ровно на удар.** Сетка из `track_structure.py`, а не «каждые 0,5 с». При 130 BPM доля длится 0,46 с, при 91 BPM — 0,66 с: в медленном треке кадр успевает прочитаться.
- **Хук — до дропа.** Обещание, которое ролик потом докажет («Весь этот ролик — код»). Нулевой кадр уже в движении, строка читается к первой секунде. Титр на неподвижном фоне не годится: зритель уходит раньше, чем дочитает.
- **Главное движение — на дроп,** тихое действие (печать строки) — в брейк, взрыв или смена секции — на возврат бита, знак — на начало новой фразы трека.
- **Цель подлёта видна заранее.** Камера летит к тому, что уже в кадре. Ничего не выползает сбоку, никаких телепортов камеры под вспышкой.
- **Один ход камеры, одно направление.** Весь ролик течёт в одну сторону. Другое направление — только с причиной: щелчок, удар, новая глава.
- **Кадры-генераторы вместо стоковых.** `engine/lib/shots.js` даёт 21 живой кадр, нарисованный кодом, и 8 тонов тёплой гаммы. Соседние кадры — разного тона. Чужих стоковых роликов и картинок не брать.
- **Без «дыхания» ради заполнения.** Покачивание, мерцание и плавание в ожидании читаются как «видео ждёт». Между входом и выходом что-то происходит: открывается новая информация, едет камера, срабатывает действие.
- **Пауза перед кульминацией** 0,3–0,75 с. Без неё действие сразу перескакивает в результат.
- **Один кадр — один раз.** Если результат сам становится входом (скан → фото), карточку входа перед ним не ставить.
- **Фон спокойный.** Свет фона не прыгает под музыку, линий «для красоты» нет.

Законы стыков, каскадов текста и курсора — [references/motion-laws.md](references/motion-laws.md). Шоурил одним дублем целиком — [references/one-take-showreel.md](references/one-take-showreel.md). Стекло шейдером (рифлёное, волнистое, матовое, блоки) — [references/glass.md](references/glass.md).

## Грабли рендера

Рендер идёт в несколько потоков и запрашивает кадры не по порядку. Отсюда почти все грабли.

| Симптом | Причина | Решение |
|---|---|---|
| Кадры дёргаются, частицы «прыгают» между рендерами | состояние копится от кадра к кадру | **кадр — чистая функция времени**: `render(t)` всё считает заново; без `requestAnimationFrame`, `Date.now`, `Math.random` и накопленной физики; случайность — `rng(seed)`, пружины — в замкнутой форме из `motion.js` |
| Рендер 45 с ждёт и падает по таймауту | движок ждёт GSAP-таймлайн, а его нет | на корне `data-no-timeline` и `data-duration`, перемотка — `bindSeek(render)` из `motion.js` |
| Видео на экране замерзло на одном кадре | `drawImage(video)` в canvas или `<video>` внутри секции с таймингом | видео на 3D-экран — только `THREE.VideoTexture`; сам `<video>` — прямо в `#root`, вне секций |
| Кириллица в canvas ушла в засечки | шрифт не загружен до рисования | до первого рисования `await document.fonts.load('600 64px Manrope', 'АБВГДЕЁЖЗабвгд0123')` — с образцом кириллицы |
| Стробоскоп из копий на быстром пролёте | мало подкадров | подкадровый смаз: 6–16 подкадров на кадр, больше — чем быстрее камера; затвор — полкадра |
| Цвет видео человека «уехал» | ACES, хроматическая аберрация, ореолы, цветные заливки поверх | пост без них; мягкое плечо по максимуму канала с сохранением оттенка, виньетка, статичное зерно |
| Исходник стал другого оттенка | его красили | яркость исходника — только скаляром, оттенок не трогать никогда |
| Белая вспышка на стыке | под полупрозрачными сценами виден белый фон страницы | у `#root` всегда непрозрачный фон из пака |
| MP4 на 8 секунд весит 50 МБ | зерно меняется каждый кадр | зерно статичное |
| Текст на 3D-предмете мыльный | надпись на общей текстуре, мало пикселей на букву | надпись — отдельной наклейкой до 4096 px, анизотропия, суперсэмплинг |
| Bloom копится и пересвечивает | проход пишет в уровень, который сам читает | писать в отдельный буфер |
| Тонкие линии размыты | `--quality standard` | `--quality high` |
| Пустой canvas WebGL в кадре | буфер очищается до снимка | `preserveDrawingBuffer: true` |
| «Invalid or unexpected token» | закрывающий тег скрипта внутри встроенного JS (даже в комментарии) | не писать его в `.js`; в шаблоне — `<\/script>` |

## Чего не делать

- Не запускать `npx hyperframes` напрямую и команды `init`, `auth`, `cloud`, `tts`, `transcribe`, `remove-background`: они ходят в сеть или ставят модели. Только `npm --prefix engine run check|snapshot|render`.
- Не скачивать стоковые видео, картинки и шрифты. Нет материала — рисуем кодом или говорим, чего не хватает.
- Не показывать в кадре чужой интерфейс, чужой логотип и личные данные людей.
- Не называть ролик готовым по снимкам `snapshot` — только по кадрам из MP4.
- Не менять исходники человека и не писать вне `$WORK/<проект>/`.

## Скиллы HyperFrames и Remotion

В поставку они не входят: их авторы обновляют их сами. Если человеку нужно глубже, чем дают шаблоны, можно поставить их из первоисточника. **Только с согласия: это сеть.**

```bash
npx skills add heygen-com/hyperframes     # HyperFrames: композиция, анимация, CLI
npx skills add remotion-dev/skills        # Remotion: ролики на React
```

Спросить так: «Поставить скиллы HyperFrames с GitHub? Это скачивание из сети. Удалить можно, стерев их папку в `.claude/skills/`». Правила этого скилла (без сети, без облака, `--describe false`) действуют и поверх них.
