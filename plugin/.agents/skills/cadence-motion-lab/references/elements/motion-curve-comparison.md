# Сравнение поведения и следов

## Назначение

Объяснить разницу между двумя законами движения при равных условиях. Семейство: сравнение.

## Входные данные

Две функции E1/E2, одинаковые start/end и duration, подписи, число samples, график progress.

## Параметры и компоновка

Одинаковые объекты и длина пути; linear и ease-out допустимы как понятная пара; точки следов взяты через равные интервалы времени.

## Контракт исполнения

Все размеры заданы относительно ширины W и высоты H кадра. Пак задаёт цвета и шрифты; safe zones берутся из design/tokens.json и ограничений сцены. До движения загрузить шрифты и материал, вычислить окончательный layout. Для Instagram Reels/TikTok 9:16 рабочая безопасная область важного содержания: x=0.06W…0.82W, y=0.15H…0.75H (при 1080×1920 примерно x=65…886, y=288…1440). Это консервативные рабочие поля, не официальная универсальная спецификация. Заголовки, captions, CTA, логотип, лицо и существенные детали помещаются в пересечение этой области с safe zones токенов и сцены. Фон и несущественный декор могут доходить до края. Геометрические defaults ниже адаптировать к доступному прямоугольнику; не сохранять размер карты ценой перекрытия интерфейсом. При наличии фактического UI уточнить поля.

Расписание задаёт start, entry, hold, exit и смысловые события; длительности выбираются по речи, читаемости и сетке музыки, фиксированная длина сцены не требуется.

Локальный progress `u=clamp((t−start)/duration,0,1)`; при t<start вернуть исходное состояние; при duration=0 и t≥start состояние сразу конечное. `E(u)=1−(1−u)^3` для мягкой остановки, `E(u)=u` для равномерного движения; `lerp(a,b,u)=a+(b−a)u`. Один кадр полностью вычисляется из t, входных данных и seed. Без накопленной физики, Date.now, независимых CSS timers и несидированной случайности.

## Слои

Две дорожки → объекты → следы → график тех же функций → подписи.

## Порядок анимации

Вход: установить равные условия. Действие: оба объекта стартуют одновременно; следы раскрываются по времени. Hold: сравнить конечные траектории и график. Выход: оставить выбранный режим или итоговое правило.

## Вычисление состояния

Число samples — целое N≥2, j=0…N−1; меньший N привести к 2. x_i(u)=start+(end−start)×Ei(u); sample_j=Ei(j/(N−1)). На графике (u,Ei(u)); marker вычисляется той же Ei. duration>0 для движущегося сравнения; при duration=0 сразу конечное состояние обеих дорожек, без промежуточных следов. Не принимать отрицательную длительность или нечисловой результат Ei.

## Критерии результата

График соответствует движению; время/путь равны; сгущение точек объясняется скоростью. Проверить начало, события изменения, завершение каждого entry/exit, стыки по соседним кадрам и устойчивый финал в итоговом MP4. Если внутри есть видео, проверить, что оно играет. Один и тот же t после разных порядков seek должен давать одинаковую композицию.

Проверить экспортированный файл через ffprobe: по умолчанию 1080×1920, SAR 1:1, DAR 9:16 и правильная ориентация с учётом rotation metadata. Промпт и скриншот телефона не подтверждают параметры файла; возможность перемещения в Instagram не доказывает ошибку пропорций.

## Когда отказаться и как исправлять

Не называть linear рывком: постоянная скорость и скачок ускорения — разные свойства. При неверных следах убрать равномерную выборку по x. Если локальная диагностика не объяснила сбой, искать в публичной официальной документации конкретного API или renderer по симптому и версии. Исправить причину, затем повторить проверку затронутого участка в итоговом ролике.
