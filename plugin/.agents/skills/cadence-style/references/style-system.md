# Шаблон DESIGN.md стиля

`pack.json` хранит токены: цвета, шрифты, радиусы. Но стиль — это ещё и то, как всё движется, сменяется и генерируется. Эти правила пишутся рядом с паком в `$WORK/packs/<id>/DESIGN.md`. Агент читает его перед каждой сценой в этом стиле.

Скопировать каркас ниже и заполнить по итогам выбора стиля ([choose-style.md](choose-style.md)). Раздел, о котором человек ничего не решал, заполнить разумным значением по умолчанию и пометить «по умолчанию».

```markdown
---
status: draft            # draft — правила ещё меняются; frozen — менять только новой версией
version: <id>.v0.1
pack: <id>               # и второй режим, если есть: <id>-accent
---

# <Название стиля>

## 1. Цвет
Роли из pack.json одной таблицей: фон, поверхность, текст, второстепенный, акцент, линия.
Что выделяется акцентом (одно слово заголовка, цифры, активный пункт) и что никогда.
Режимы: строгий / с акцентом — когда какой.

## 2. Шрифт
Одно семейство, начертания (например 500 текст, 600 подписи, 700 заголовки).
Регистр: обычный. Кегли для 16:9 и 9:16. Что моноширинным (код, время).

## 3. Логотип и поля
Файлы, минимальный размер, поля вокруг знака, где стоит в кадре.
Водяной знак: поля не меньше, чем у аватара, иначе плеер обрежет края.

## 4. Характер движения
| Что | Длительность | Кривая |
|---|---|---|
| появление текста | 0,3–0,5 с | выход быстрый, остановка мягкая |
| смена карточек | 0,4–0,6 с | |
| переход между сценами | 0,4–0,6 с | |
| пауза на чтение | не меньше 1,5 с на строку | |
Одно семейство кривых на весь стиль. Одновременно двигаются не больше трёх групп.

Пружины по ролям (жёсткость · затухание; по умолчанию — значения Cadence, `design/tokens.json` → `motion.springs`):
| Роль | Значение | Что в этом стиле так движется |
|---|---|---|
| follow | 900 · 50 | |
| settle | 280 · 22 | |
| soft | 260 · 24 | |
| pop | 520 · 16 | |
| fade | 420 · 32 | |
| lead / trail | 620 · 36 / 190 · 19 | |
Шаг очереди: 45 мс. Строгий стиль — меньше перелёта (затухание выше), игривый — больше. Своя роль — новой строкой, с причиной.

## 5. Физика объектов
Вес: лёгкое (подписи) приходит быстро, тяжёлое (карточки, числа) — с инерцией.
Отскок: есть/нет и насколько. Тени и глубина: плоско или слои.

## 6. Трансформации
Чем объект появляется и уходит: сдвиг, масштаб, маска, инверсия.
Направление: в какую сторону идёт «вперёд» (например, всё уезжает влево).
Чего нет в этом стиле (вращения, резиновые деформации, блёстки).

## 7. Переходы
2–4 перехода с именами, длительностью и звуком.
Переход — накладка поверх жёсткой склейки: сам ролик режется встык, накладка прячет стык.
Когда какой: смена темы, смена места, возврат.

## 8. Безопасные зоны
16:9 и 9:16: поля, где не стоят текст и логотип; зона подписей; зона интерфейса площадки.

## 9. Цвет для генерации
Цвет как отношение, а не HEX: «тёмный низкоконтрастный фон, один тёплый светлый акцент,
кожа естественная». Нейросеть не попадает в HEX, но держит отношение.
Чего избегать в промпте (кислотные цвета, неон, если стиль строгий).

## 10. Изолированные слои
Что генерируется отдельно и собирается в движке: фон, объект, текст, частицы.
Текст и логотип никогда не генерируются нейросетью — только движком.
Объект — на однотонном фоне, чтобы его можно было вырезать.

## 11. Ассеты (Asset Manifest)
| Ассет | Файл | Откуда | Лицензия |
|---|---|---|---|
| логотип | logo/lockup.svg | человек | его |
| знак | logo/mark.svg | человек | его |
| шрифт | fonts/<Имя>-<начертание>.ttf | engine/fonts | OFL |
| референсы движения | motion-refs/*.mp4 | свои рендеры | — |
| тексты | copy.md | утверждённые строки | — |
| опорный кадр | reference-frame.png | ролик человека | его |

## Журнал версий
- v0.1 — дата — что решено.
```

## Версии стиля

- `draft` — правила обсуждаются, сцены в этом стиле считаются пробой.
- `frozen` — стиль утверждён. Любая правка — новая версия (`v1.0` → `v1.1` для уточнения, `v2.0` для смены цвета или шрифта) и строка в журнале. Старые ролики остаются на своей версии.
- Заморозить стиль — решение человека, не агента.

## Чего не делать

- Не дублировать токены: HEX и шрифты живут в `pack.json`, DESIGN.md на них ссылается ролями.
- Не записывать правило, которое человек не принимал, как утверждённое: такое помечается «по умолчанию».
- Не класть DESIGN.md стиля в папку выпуска: следующее обновление его заменит.
