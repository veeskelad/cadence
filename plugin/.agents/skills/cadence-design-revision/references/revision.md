# Аудит и изменение

## Граница

Режим исправления сохраняет направление; развитие усиливает систему без смены идентичности; новое направление допускается только в соответствующем запросе. Зафиксировать удачные якоря, факты, кадрирование работ, text/copy, pack и события. Для приложения также сохранить маршруты, поля, действия, отслеживание и юридический текст; для видео — реальные тайминги причин/результатов и нужный порядок смысла.

## Реестр дефектов

```text
location:
observed_problem:
impact_on_viewer:
property_causing_it:
preserved_invariants:
minimal_change:
verification:
```

Не писать «дёшево» вместо причины. Назвать: недифференцированные уровни; обрезанная буква; случайная рамка; спорящие группы; скачок после загрузки; неверная единица; выдуманная метрика; слишком мелкое существенное; медленный ответ; лишняя декорация; смешанная система света/радиусов.

## Порядок

Исправлять угрозу пониманию/корректности прежде атмосферы: неверный факт/перекрытие UI → текст и иерархия → оси/gap/crop → роли контраста → причинность движения → материал/декор. Не менять шрифт автоматически: если принятая антиква даёт дефект, сначала проверить глифы, weight, wrapping, размер и clearance.

Карточки объединить там, где их граница не означает отдельный объект. Плотный список группировать по задаче; не заставлять все строки иметь независимую рамку. Согласовать внешние/внутренние радиусы и направленный свет. Числа/единицы брать из данных, не рандомизировать для правдоподобия. Generic label убрать, если его удаление не теряет смысл; навигационную метку оставить, если она помогает.

Новый выразительный приём применять только к конкретной цели: большая типографика — главной мысли; маска — раскрытию; глубина — отношению планов; spring — реакции массы; grain — материалу. Постоянная анимация не исправляет скучное объяснение. Предпочесть самый простой механизм, сохраняющий смысл.

## Совместимость и приёмка

Не запускать обновление стеков ради стиля. У каждого property остаётся один owner, слои и ресурсы имеют известный контракт. Сохранить старые стабильные части, если переход на новый локальный рецепт ломает поведение. Воспроизводимость выбирать явно в проекте: входы/пак/recipe_id/renderer/seed; legacy-profile не активировать по похожему названию.

Проверить самый длинный текст, плотный кадр, критический стык и новый конечный результат. Для web/app проверить actual control/keyboard/state; для MP4 — сам экспорт, seek, playback, UI-overlay, cover crops и dimensions/SAR/DAR/rotation. В Reels/TikTok существенное внутри x0.06W…0.82W/y0.15H…0.75H; ограничения текущей площадки имеют приоритет над старыми геометрическими defaults. Итог: названный дефект исчез, содержание/бренд не повреждены, работа вне затронутого участка сохранена.
