# Планирование разделов веб-поверхности

## Состав

Сначала сформулировать целевое действие или понимание. Каждый раздел отвечает на отдельный вопрос: что это; для кого; как действует; чем подтверждено; как продолжить. Маркетинговая последовательность «внимание → интерес → желание → действие» уместна для продажи; обучающая или архивная страница может иметь другую последовательность. Не выдумывать testimonials, logos, цены, гарантии и метрики ради блока доказательств.

Составить реестр всех запрошенных разделов. Запись:

```text
section_id:
viewer_question:
content_exact:
evidence_asset:
primary_reading_anchor:
layout_relation:
media_frame_and_crop:
background_role:
cta_intent_or_none:
shared_contract:
responsive_order:
image_or_brief_output:
acceptance:
```

## Компоновка

Первый экран должен одновременно показывать сообщение, главный материал и существенное действие, если оно требуется. Определить ширину и переносы совместно с размером изображения. Длинный заголовок не обязательно исправляется уменьшением шрифта: убрать лишнюю мысль или выделить ей следующий раздел. Антиква/центрирование/чистый текст допустимы по бренду и задаче.

Выбирать отношения объектов: тезис сверху и материал ниже; две сопоставимые области; крупный материал с боковым пояснением; типографический плакат; большая область и вспомогательные; последовательная галерея; изображение как фон с защищённым текстом. Смена отношений создаёт ритм без смены бренда. Не добавлять каждый раз плашку над заголовком или одинаковую тройку карточек автоматически. Намеренный повтор допустим для одинаковых сущностей.

Сетка строится по реальному числу элементов. Каждой ячейке назначить существующий content_id; случайная пустая ячейка — ошибка, осмысленная зона воздуха — правило композиции. Не менять смысловой порядок ради плотной автоперестановки. Для длинного набора выбрать группировку, раскрытие, обзор/деталь, навигацию или отдельный раздел; не уменьшать весь текст.

Общее: один контрастный порядок, палитра/радиус/линии из контракта. Вариативное: положение героя, масштаб материала, плотность и роль фона. Дополнительная деталь должна иметь задачу узнавания или чтения; не нужна обязательная квота «неожиданного момента».

## Изображения и фон

Определить системные роли медиа: контекст, свойство предмета, собственный интерфейс, человек, атмосфера. Повторяемые роли имеют совместимые aspect ratios и crop. Исходную работу человека не перекрашивать. Для нового атмосферного материала можно описать согласованный свет/палитру, сохраняя утверждённый объект.

Текст поверх изображения требует тихой области, подложки либо локальной маски. Проверить худшую контрастную область, а не средний цвет кадра. Типографика, геометрия и кодовая схема могут сами быть полноценным материалом: генерация фотографии не обязательна.

## Выход и проверка

Сложные разделы отдавать отдельными читаемыми листами; обзор нужен только для связи. Для каждого листа зафиксировать отношение сторон/экранный размер, точный текст и путь. При недоступной генерации завершить briefs и явно отметить состояние. При неясной детали сначала проверить исходное разрешение; приближение сохраняет существующий дизайн, новая генерация меняет доказательство. Перегенерацию делать лишь с разрешением и сохранённым контрактом.

Сравнить весь набор: каждый нужный раздел есть, текст читается, смысловое действие ясно, CTA не конкурируют, первичный viewport не перегружен, меньший размер сохраняет порядок, поля и края не обрезаны. Статическая картинка не доказывает responsive, hover, кликабельность или SEO. Если композиции входят в Reels/TikTok, применять safe area x0.06W…0.82W/y0.15H…0.75H и проверять UI-overlay/cover; готовый MP4 проверить по файлу.
