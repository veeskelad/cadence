# Экран на фото своего устройства

Ролик на 12–16 секунд: настоящее фото ноутбука или телефона человека, на его экран по четырём углам вклеена композиция (обычно — [сборка на экране](screen-build.md)), камера стоит в двух неподвижных планах с одной склейкой, а в конце готовый результат вылетает из экрана на весь кадр и играет дальше. Поверх — субтитры трека или призыв в конце.

Это обёртка, а не отдельная форма: что показывает экран, решает рецепт содержимого. Вместе они — одна структура.

## Брать и не брать

Брать:
- нужно «агент делает это на моём ноутбуке» без съёмки видео;
- есть хорошее фото своего устройства и композиция экрана 16:10 (ноутбук) или 9:19,5 (телефон).

Не брать:
- фото нет, а сгенерированное устройство не годится: ракурс и свет не совпадут со вклейкой — тогда нейтральное устройство кодом (`device-stage.md`);
- нужна камера, которая летает вокруг устройства, — по фото это не сделать.

## От человека

- фото **своего** устройства: экран прямо в кадре, рамка экрана тёмная, на экране может быть что угодно — его закроет вклейка;
- логотип на корпусе вне кадра или закрыт — правило «Права на материалы» в каталоге: своё фото можно, чужой знак в кадре нельзя. Если знак виден, сказать человеку;
- композиция экрана или материал для неё;
- трек, по желанию — текст призыва.

Фото снимать в полном разрешении камеры, без уменьшения: на укрупнении нужен каждый пиксель.

## Порядок

`$WORK` — рабочая папка человека (как её найти — `cadence-motion`, «Где лежат файлы»). Пути в командах `npm --prefix engine` — полные: скрипт рендера запускается из папки `engine/`.

1. **Углы экрана.** Скрипт ищет переход «тёмная рамка → интерфейс» и ставит прямые по рёбрам; углы — их пересечения:
   ```bash
   node skills/cadence-structures/scripts/screen_corners.mjs find "$WORK/<проект>/build/corners-find.json"
   ```
   В `corners-find.json` — путь к фото, папка для проверки и четыре окна поиска (формат — в начале скрипта); пути — относительно папки самого файла, например `"photo": "../input/photo.jpg"`, `"out": "corners"`. Окна задаются на глаз по уменьшенному фото с запасом ~100 px. Скрипт печатает `quad` и пишет `screen-quad.png`: зелёная рамка должна лечь точно по краю интерфейса. Ребро не нашлось — расширь окно или подними пороги `dark` и `ui` для светлого снимка.
2. **corners.json** в `$WORK/<проект>/build/` и проверка:
   ```json
   {
     "plate": "plate.jpg",
     "crop": [0, 0, 3213, 5712],
     "quad": [[381.1, 1348.2], [2747.4, 1508.3], [2812.1, 2909.7], [543.9, 3193.5]],
     "overscan": 6,
     "grade": "eq=saturation=1.05",
     "sharpen": "nlmeans=s=3:p=7:r=15,cas=0.7",
     "glass": { "glare": 0.05, "vignette": 0.14 }
   }
   ```
   ```bash
   node skills/cadence-structures/scripts/screen_corners.mjs check "$WORK/<проект>/build/corners.json" --photo-size 4284x5712
   ```
   - `quad` — углы в пикселях исходного фото: левый верх, правый верх, правый низ, левый низ.
   - `crop` — кусок фото в пропорции кадра (9:16 или 16:9); он и есть кадр при масштабе камеры 1.
   - `overscan` — на сколько пикселей экрана вклейка заходит на рамку, чтобы по краю не светился старый интерфейс.
   - `grade` и `sharpen` — фильтры ffmpeg: цвет фото под пак и шумодав с резкостью (ночное фото телефона в 100 % мягкое и шумное). Цвета экрана они не трогают.
   - `glass` — лёгкий блик и виньетка стекла поверх экрана, не больше 0,15.
3. **Подложка.** Готовится один раз, исходное фото не меняется:
   ```bash
   ffmpeg -i "$WORK/<проект>/input/photo.jpg" -vf "crop=3213:5712:0:0,eq=saturation=1.05,nlmeans=s=3:p=7:r=15,cas=0.7" -q:v 2 "$WORK/<проект>/build/plate.jpg"
   ```
4. **Экран.** Композиция 1920×1200 по рецепту содержимого, рендер вдвое плотнее (3840×2400) — в `screen-build.md`. Время экрана и время внешнего ролика — одно: оба читают один список времён шагов, и звук берёт события оттуда же.
5. **Внешний ролик** (ниже — «Композит»), звук, рендер, проверки.

## Композит

Код геометрии — в библиотеке, сборка копирует её в `build/lib/`:
- `engine/lib/homography.js` — `quadMatrix3d(W, H, quad)` для CSS `matrix3d`, `project()` — куда попадает точка экрана, `overscanQuad()`, `photoToFrame()` — углы с фото в пиксели кадра, `lerpQuad()`;
- `engine/lib/camera.js` — `anchored()` — план якорем, `keepInside()`, `frameTime()`, `flyOut()`.

**Экран на фото.** Углы переводятся из фото в кадр (`photoToFrame(quad, crop, 1080)`), расширяются на `overscan` (`overscanQuad`) и дают матрицу `quadMatrix3d(1920, 1200, q)`. У элемента экрана — `transform-origin: 0 0` и `object-fit: fill`. Видео экрана 3840×2400 стоит под CSS-размером 1920×1200: при укрупнении берётся его полное разрешение.

**Камера.** Видео обязаны быть прямыми потомками корня, поэтому общего контейнера-камеры нет. Камера — CSS-переменные на корне (`--cx`, `--cy`, `--ck`); фото, экран и стекло применяют `translate(cx, cy) scale(k)` и затем свою матрицу.
- План задаётся якорем: точка экрана стоит в нужной точке кадра при масштабе `k` — `anchored(точка, [x, y], k)`, потом `keepInside()`, чтобы фото не отрывалось от краёв.
- Два неподвижных плана: общий `k ≈ 1,3`, укрупнение `k ≈ 2,0`, одна склейка между ними. Неподвижный план — два ключа, склейка — смена ключа.
- **`k ≤ 2`** — пока на пиксель готового кадра приходится не меньше ~1,5 пикселя фото (`photoPxPerFramePx(cropW, 1080, k)`). Кроп шириной ~3200 px при `k = 2` даёт как раз 1,5; кроп меньше — и укрупнение надо уменьшать.
- Точка экрана, за которой следит взгляд, — в центре кадра по ширине и в верхней трети по высоте. Текст — внизу, над клавиатурой.
- Ключи на каждый кадр — `tl.set` со временем `frameTime(f, 30)`: время округляется вниз. При округлении вверх ключ срабатывает кадром позже, и каждый третий кадр повторяет прошлый.

**Вылет.** Готовый результат вылетает из экрана на весь кадр.
- Углы кадра результата на экране (через `project()` и камеру) → углы всего кадра; на каждый кадр вылета — `lerpQuad(экран, кадр, w)` и своя `matrix3d` карточки 1080×1920.
- `flyOut(t, t0, 0.8, R)`: вылет 0,8 с по кривой `power3.inOut`, скругление углов карточки уходит в 0.
- Карточка вылета — `<video>` **того же файла**, что на экране, с тем же временем результата: склейки внутри вылета нет. До вылета карточка прозрачна, клип длиннее 0,7 с.
- Тёмный слой между устройством и карточкой: непрозрачность 0 → 0,8 за время вылета.

**Текст поверх.** Субтитры трека — фраза до двух строк над клавиатурой, слово загорается акцентом пака в такт (время слов — локальный Whisper по треку, слова сверять на слух: в песне он путается). Без плашки, тень в несколько слоёв держит текст на клавишах. Призыв встаёт на месте субтитров вместе с вылетом и стоит до конца. Заголовок с подзаголовком поверх всего ролика не нужны.

## Рендер

```bash
# экран 3840×2400 — по screen-build.md
# внешний ролик вдвое плотнее
npm --prefix engine run render -- "$WORK/<проект>/build" --resolution portrait-4k --video-frame-format png --crf 10 --no-best-effort --output "$WORK/<проект>/out/draft-4k.mp4"
# в 1080: lanczos и лёгкая резкость; звук — готовый микс
ffmpeg -i "$WORK/<проект>/out/draft-4k.mp4" -i "$WORK/<проект>/out/mix.wav" -map 0:v -map 1:a \
  -vf "scale=1080:1920:flags=lanczos,cas=0.35" -c:v libx264 -preset slow -crf 13 -profile:v high \
  -pix_fmt yuv420p -movflags +faststart -c:a aac -b:a 256k -shortest "$WORK/<проект>/out/device.mp4"
```

- Сборка копирует медиа к себе: после перерендера экрана или звука — пересобрать внешний ролик.
- Промежуточный 4K удалить сразу после уменьшения.
- Рендер — по одному за раз: параллельные рендеры отнимают друг у друга память.

## Звук

Через `cadence-sound`. Трек главный, события шагов на экране — тихие, из того же списка времён. Вылет — один воздушный звук, пик на середине пути. Эффекты не поднимают общую громкость.

## Проверки

- Линт и снимки на склейке, во время вылета и после: `npm --prefix engine run snapshot -- "$WORK/<проект>/build" --at 6.1,6.3,11.4`.
- Лист кадров через вылет. **Повторы кадров на движении** — PSNR соседних кадров:
  ```bash
  ffmpeg -i "$WORK/<проект>/out/device.mp4" -i "$WORK/<проект>/out/device.mp4" -filter_complex "[1:v]trim=start_frame=1,setpts=PTS-STARTPTS[b];[0:v][b]psnr=stats_file=$WORK/<проект>/out/psnr.log" -f null -
  ```
  На участке, где камера или карточка движутся, PSNR соседних кадров выше 50 дБ — это повтор кадра (обычно ключ, округлённый вверх).
- `freezedetect` на неподвижной камере ложно помечает куски, где меняется только маленький объект на экране. Это не брак — проверять кропом глазами.
- **Кроп 1:1** экрана и фото в 2–3 моментах (`crop=540:540:x:y` без масштаба): мыло и швы видны только так.
- Громкость и истинный пик — `ebur128`: эффекты под треком не добавляют громкости.

## Частые ошибки

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| нарисованный свет экрана на клавиатуре, тень под кадром | на фото свет уже настоящий, копия читается нарисованной | поверх фото ничего, кроме лёгкого блика стекла |
| переворот экрана в 3D | выглядит дёшево | экран не отрывается от устройства |
| наезд камеры сквозь экран | мылит, взгляд теряется | камера стоит, одна склейка |
| много панелей на экране | взгляд разбегается | один объект в центре (`screen-build.md`) |
| зерно поверх кадра | шумит и съедает битрейт | без зерна |
| призыв весь ролик | мешает смотреть | призыв — с вылетом и до конца |
| сгенерированное фото устройства | свет и ракурс не совпадают со вклейкой | своё фото |
| `k` больше 2 на кропе ~3200 px | фото растянуто | меньше укрупнение или кроп крупнее |
