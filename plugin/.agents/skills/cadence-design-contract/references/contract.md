# Самостоятельное описание системы

## Процедура

1. Определить, кто использует документ: генератор статического изображения, агент реализации или автор следующей сцены. От этого зависит контракт поведения.
2. Собрать утверждённые значения пака и видимые повторения. Для каждого правила указать область применения: весь проект, компонент, конкретная сцена или вариант.
3. Описать роль, значение и проверку. «Мягкая поверхность» без цвета/края/глубины недостаточна; точные значения без функции также недостаточны.
4. Разделить вид и действие. Изображение показывает одну фазу; изменения описываются явными состояниями и событиями.
5. Проверить на самом длинном тексте, наиболее плотном компоненте и меньшем формате текущей задачи. Исправить конфликт, не переписывая весь бренд.

## Формат

```text
contract_id и версия рабочей записи:
scope: scene / screen-set / identity
purpose и audience:
authority: что утверждено; что допускает вариацию
assets: локальный путь, роль, права использования, глифы
palette: role → value → where → contrast_pair
type: role → available_font → weight → scale_rule → line_wrap
space: container → bounds → alignment → padding → gap
shape: role → radius/stroke → nested_relation
surface: layer → fill → edge → light → fallback
components: name → content → states → dimensions → constraints
behavior: trigger → from/to → anchor → time_source → completion
formats: target → safe_area → adaptation → crop
content: точные строки/данные и происхождение
acceptance: наблюдаемые проверки
unresolved: неизвестное и способ безопасного исполнения
```

Для статического экрана behavior является намерением будущей реализации. Не писать «работает» по рисунку. Для MP4 clock — время кадра; для web-preview — действие/scroll с доступной альтернативой. Раздельные движки могут существовать при едином владельце каждого свойства; запрещено конкурирующее управление одним transform.

Адаптация размеров задаётся относительно доступной области. Для нового aspect ratio переупорядочить смысловые блоки, сохранив роли и материал; не растянуть готовую картинку. Для Reels/TikTok важное внутри x0.06W…0.82W/y0.15H…0.75H и актуального UI. Проверить отдельные кропы cover; MP4 проверить dimensions/SAR/DAR/rotation.

Если компонент имеет loading/empty/error, включать состояния, которые реально нужны сценарию. В настоящем интерфейсе добавить клавиатуру, focus, обратное действие и уменьшенное движение. Для одного видеокадра не строить неиспользуемую веб-функциональность.

Контракт не объявляет похожую стилистику официальной системой другого производителя. При настоящем встраивании в существующее приложение использовать его установленную библиотеку и токены. Недостающая зависимость — конкретный вопрос реализации, не основание заменить стек. Подключение внешнего конструктора отдельно разрешается человеком.
