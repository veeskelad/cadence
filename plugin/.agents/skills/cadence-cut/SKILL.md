# Нарезка живого видео

**Где запускать команды.** Корень Cadence: `${CLAUDE_PLUGIN_ROOT}`. Если выше стоит путь к папке — Cadence стоит плагином: команды этого навыка запускать из этой папки (`cd` туда), свои файлы человека — в `$WORK`, не в ней. Если видна сама запись в фигурных скобках — это папка выпуска или исходников, команды запускаются из неё.

Человек даёт своё видео — получает новый MP4 без пауз, по желанию с субтитрами и музыкой. Все скрипты лежат в `scripts/` в корне проекта, запускаются из корня, работают на этой машине без сети и без ключей. Исходник никогда не меняется: результат — новые файлы в `work/<проект>/out/`.

## 1. Спросить одно

«Пришлите путь к видео (можно перетащить файл в окно)». Остальное — по ходу и только если нужно: есть ли отдельный звук с петлички, нужны ли субтитры, есть ли трек для музыки.

Какой путь выбрать:

| На руках | Путь |
|---|---|
| один заход, нужно убрать паузы | шаги 3–8 этого навыка |
| запись с несколькими дублями одной фразы, оговорки, «стоп, заново» | раздел «Запись с дублями» ниже, потом шаги 5–8 |
| длинное видео без речи, нужен короткий ролик | раздел «Хайлайт из видео без речи» ниже |

Название проекта придумай сам из имени файла (`take1.mp4` → `take1`), латиницей, без пробелов.

## 2. Проверить инструменты (только чтение)

```bash
ffmpeg -version
python3 --version
python3 -c "import sys; sys.path.insert(0, 'scripts'); import cadence_paths as c; print(c.work_root())"
```

Третья команда печатает рабочую папку — дальше она `WORK`. Чего-то нет — назови одну недостающую вещь и команду установки, ничего не ставь без согласия:

- нет `ffmpeg` — macOS: `brew install ffmpeg`; Windows: `winget install Gyan.FFmpeg`; Linux: `sudo apt install ffmpeg`;
- для сведения звука и музыки нужен `numpy`: `python3 -c "import numpy"`; нет — `python3 -m pip install numpy`;
- Whisper для субтитров проверяет сам скрипт (шаг 5) и подсказывает команду.

## 3. Скопировать видео в рабочую папку и снять паспорт

Исходник человека не трогаем: копируем в `WORK/<проект>/in/` и записываем отпечаток, чтобы потом показать, что файл не изменился.

```bash
python3 scripts/new_project.py <проект> --copy "<путь к видео>" --dry-run   # план: куда и что
python3 scripts/new_project.py <проект> --copy "<путь к видео>"             # копия + сверка sha256
shasum -a 256 "WORK/<проект>/in/<файл>"        # отпечаток для сверки в конце; Windows: certutil -hashfile <файл> SHA256
python3 scripts/inspect_video.py "WORK/<проект>/in/<файл>"
```

Звук с рекордера и трек для музыки копируются той же командой: `--copy "<видео>" "<звук>" "<трек>"`.

Паспорт расскажет обычным языком: длина, разрешение, вертикальное или нет, частота кадров, громкость в LUFS, сколько пауз и есть ли чёрные кадры. Перескажи человеку главное в двух-трёх фразах и пункты из «На что обратить внимание».

Одна звуковая дорожка в файле — это только про файл. Не говори «отдельного микрофона нет»: петличка или рекордер часто пишут отдельным файлом. Спроси, был ли такой.

## 4. Паузы: сначала план, потом нарезка

```bash
python3 scripts/silence_cut.py "WORK/<проект>/in/<файл>" --dry-run
```

План покажет: сколько резов, сколько секунд уйдёт, какая выйдет длина, первые паузы с таймкодами. Ничего не пишется. Покажи цифры и спроси: «Режем так?»

Если результат не нравится, крутим ручки и снова `--dry-run`:

| Что не так | Что поменять |
|---|---|
| режет посреди фраз, съедает тихие слова | `--threshold -45` (тишиной считается только совсем тихое) |
| паузы почти не режутся, фон шумный | `--threshold -30` |
| слишком рублено, нет вдоха между фразами | `--min-silence 0.7` и/или `--padding 0.2` |
| хочется плотнее, как в коротких роликах | `--min-silence 0.3 --padding 0.08` |

Когда человек согласовал план, запусти ту же команду без `--dry-run`. Видео перекодируется (резы точные до кадра), на стыках звука — фейды по 10 мс, чтобы не щёлкало. Повторный запуск не затирает прежний результат; чтобы заменить его, нужен `--overwrite` — спроси человека.

## 5. Субтитры (если нужны)

Субтитры делаем по **уже порезанному** видео, тогда время совпадёт с итоговым роликом.

```bash
python3 scripts/captions_whisper.py "WORK/<проект>/out/<имя>-cut.mp4" --dry-run
python3 scripts/captions_whisper.py "WORK/<проект>/out/<имя>-cut.mp4"
```

- Нет Whisper — скрипт печатает одну команду установки и останавливается (код 3). Установка идёт через интернет: назови её человеку и жди согласия.
- Нет модели на диске — скрипт просит `--allow-download` (код 4) и называет размер. Тоже только с согласия. `--model base` быстрее, `small` (по умолчанию) точнее для русского.
- Язык по умолчанию русский; другой — `--lang en`. Не знаешь, на каком языке говорят (интервью, чужой ролик), — `--lang auto`: язык определит Whisper и запишет в `<имя>.words.json`. Заданный явно язык не тот, что в речи, — и получится не расшифровка, а пересказ на заданном языке, похожий на правду. Поэтому при сомнении — `auto`.

SRT собирается так: не больше 32 знаков в строке, не больше двух строк, каждый субтитр на экране хотя бы 0,8 с, новый субтитр — после паузы длиннее 0,6 с или конца предложения. Читать нужно успевать: не больше 17 знаков в секунду (`--max-cps`). Быструю реплику скрипт держит на экране дольше — до начала следующей, но не налезая на неё. Если места не хватило, скрипт назовёт номера таких субтитров: сократи в них текст или раздели фразу. Предложи человеку открыть SRT и поправить слова (имена, термины). Потом вшить:

```bash
python3 scripts/captions_whisper.py "WORK/<проект>/out/<имя>-cut.mp4" \
  --srt-in "WORK/<проект>/out/<имя>-cut.srt" --burn
```

Шрифт и размер — `--font "Arial" --font-size 60` (размер в пикселях кадра), свои шрифты — `--fonts-dir <папка>`. У вертикального видео субтитры подняты выше, чтобы их не закрыли кнопки площадки. Если человеку не нужны вшитые — отдай SRT: его можно загрузить на площадку или в монтажную программу отдельно.

## 6. Звук с петлички или рекордера (если есть)

```bash
python3 scripts/audio_sync.py "WORK/<проект>/in/<видео>" --audio "WORK/<проект>/in/<звук>" --dry-run
```

Скрипт сравнивает огибающие громкости звука камеры и рекордера и печатает сдвиг и уверенность. Высокая или средняя — сначала превью, потом полный файл:

```bash
python3 scripts/audio_sync.py "WORK/<проект>/in/<видео>" --audio "WORK/<проект>/in/<звук>" --preview
```

Превью — три коротких MP4 по 8 с (`--clip-seconds`) в начале, середине и конце, там, где говорят: картинка камеры и звук рекордера в одном файле. Человек смотрит на губы и слушает. Видео и отдельный WAV рядом — не проверка синхронизации: их сводит плеер, а не мы. Если во всех трёх совпадает — после согласия запускаем ту же команду без `--preview`: картинка копируется как есть, звук камеры заменяется звуком рекордера. В начале совпадает, а к концу уезжает — это дрейф, о нём ниже. Низкая — результат не пишется; попроси найти общий хлопок и задай сдвиг руками: `--offset 1.25`. Если скрипт пишет, что сдвиг плывёт к концу, скажи прямо: звук разойдётся с губами, это лечится в монтажной программе, а не сдвигом.

Сводить звук лучше **до** нарезки пауз: тогда паузы ищутся уже по чистому звуку петлички.

## 7. Музыка под голос (если нужна)

```bash
python3 scripts/audio_sync.py "WORK/<проект>/out/<имя>-cut.mp4" \
  --music "WORK/<проект>/in/<трек>" --duck --dry-run
```

Трек выставляется на 10 dB тише голоса (`--music-db -10`), с `--duck` он сам приглушается, пока человек говорит, и поднимается в паузах. Итог выводится к −14 LUFS (`--target`) без лимитера: если пики не дают дотянуть, скрипт честно скажет, какой громкость получилась. Короткий трек зацикливается. Права на трек — на человеке, напомни об этом одной фразой.

## Запись с дублями

Человек записал себя и повторял фразы, пока не получилось. Резать паузы мало — надо выбрать лучший заход каждой фразы. Где именно резать, решает звук (маска речи), а не время слов из Whisper: у него оно гуляет на десятую-две секунды. Как устроена маска и почему пороги такие — [references/takes.md](references/takes.md).

1. **Разбор.** `python3 scripts/takes_cut.py analyze "WORK/<проект>/in/<файл>"` — куски речи, паузы длиннее секунды (там часто начинается новый дубль), пол шума. Ничего не пишет.
2. **Текст исходника.** `python3 scripts/captions_whisper.py "WORK/<проект>/in/<файл>"` — нужен `<имя>.words.json` (`<имя>` — имя файла без расширения; SRT исходника не пригодится). Прочитай текст целиком.
3. **Выбор дублей — твоя работа, не скрипта.** Признаки:
   - спикер сам себя остановил («нет, ещё раз», «сбился») — этот заход в мусор;
   - похвалил себя после фразы («во, так норм») — бери заход **перед** похвалой, а саму похвалу вырежи;
   - целая фраза одним дыханием лучше склеенной из кусков, даже если в кусках слова точнее;
   - все заходы рваные — бери самый полный и скажи человеку, что стык будет слышен;
   - «э-э», «ну» посреди фразы — раздели кусок на два вокруг них.
4. **Запиши решения** в `WORK/<проект>/takes.json`: кусок на фразу, его текст, почему выбран и что отвергнуто — это читает человек.
   ```json
   {"source": "<файл>",
    "spans": [{"id": "S1", "in": 41.2, "out": 46.8, "text": "Сегодня покажу, как…",
               "note": "третий заход, первые два с запинкой",
               "rejected": ["30.5–35.0 сбился на втором слове", "35.6–40.1 тихо и торопливо"]}]}
   ```
   `in`/`out` можно ставить с запасом в тишину — точные края найдёт маска, — но не в соседний дубль.
5. **Проверка до показа:**
   ```bash
   python3 scripts/takes_cut.py check "WORK/<проект>/in/<файл>" --takes "WORK/<проект>/takes.json" \
     --words "WORK/<проект>/out/<имя>.words.json"
   python3 scripts/takes_cut.py fragments "WORK/<проект>/in/<файл>" --takes "WORK/<проект>/takes.json" --transcribe
   ```
   `check` ищет паузу длиннее секунды внутри куска (обычно там один заход кончился и начался следующий; сожмёшь паузу — фраза прозвучит дважды), хвост чужого дубля в начале, вход или выход посреди слова, повтор слов, громкое без слов. `fragments` режет выбранные куски на части до 5 с с запасом тишины и расшифровывает каждую отдельно: на длинном файле Whisper склеивает два одинаковых захода в одну строку, а на коротком куске повтор виден. Каждое предупреждение разбери и поправь кусок, а не показывай как есть.
6. ⛔ **Стоп.** Покажи человеку `takes.json` — текст кусков и что отвергнуто — и расшифровку. Дальше только после его «да»: какой заход звучит живее, угадать за него нельзя.
7. **Рез.** Плотность — решение человека, у скрипта нет умолчания:
   ```bash
   python3 scripts/takes_cut.py cut "WORK/<проект>/in/<файл>" --takes "WORK/<проект>/takes.json" --density natural --dry-run
   python3 scripts/takes_cut.py cut "WORK/<проект>/in/<файл>" --takes "WORK/<проект>/takes.json" --density natural
   ```
   `natural` — паузы от 400 мс сжимаются до 200 мс, речь дышит; `max` — от 160 мс до 50 мс, плотный темп. Порог паузы ниже 150 мс скрипт не примет. Весь монтаж — один проход ffmpeg, рез точно в кадр, фейд 15 мс на каждом стыке.
8. **Проверка реза — числами:**
   - в `<имя>-takes.json`: `residual_silence.max_ms` (при `max` — не больше 150 мс, при `natural` — около 200–250 мс) и `duration_drift` около нуля;
   - обратная расшифровка: `captions_whisper.py` по `<имя>-takes.mp4` — связный текст без обрубленных слов. Повторов она не видит, их ловит шаг 5;
   - кадры стыков: `python3 scripts/takes_cut.py seams "WORK/<проект>/out/<имя>-takes.mp4" --plan "WORK/<проект>/out/<имя>-takes.json"` — пары `seam-NNN-a/b.jpg`. Шорох одежды звучит как речь, его видно только глазами: рука в кадре, скачок позы — поправь кусок.

Человеку показывай числа: сколько секунд вышло из скольких, какой остаток тишины, что сказали проверки. Дальше — субтитры по `<имя>-takes.mp4` (шаг 5) и музыка (шаг 7).

## Хайлайт из видео без речи

Длинная прогулка, поездка или виды с телефона → немой черновик на 15–20 с. Скрипт оценивает окна по резкости, движению, тряске и экспозиции и выбирает лучшие с разносом по исходнику. Смысл кадра он не понимает: нужный кадр с человеком, вывеской или закатом находишь ты. Подробности и как править план — [references/highlight.md](references/highlight.md).

1. **Паспорт** — шаг 3. Нужен `numpy` (шаг 2).
2. **Обязательные моменты.** Что человек назвал обязательным, найди глазами (кадр раз в 4–5 с: `ffmpeg -i <файл> -vf fps=1/5,scale=320:-2 "WORK/<проект>/out/sheet-%03d.jpg"` — новые файлы, спроси место) и передай секунды через `--pin`. Не нашёл — спроси, а не подставляй похожий кадр.
3. **План:**
   ```bash
   python3 scripts/highlight_cut.py score "WORK/<проект>/in/<файл>" --target 17 --shot 1.4 --pin 83.5 --dry-run
   python3 scripts/highlight_cut.py score "WORK/<проект>/in/<файл>" --target 17 --shot 1.4 --pin 83.5
   ```
   В `out/<имя>-highlight/`: `plan.json`, `windows.json`, `picks.jpg`. Посмотри лист сам: смаз, пересвет, палец, одно место дважды — замени план соседним окном из `windows.json`.
4. **Ритм.** Медиана плана — 0,9–2,2 с, иначе скрипт предупредит. Первым идёт самый сильный план (так по умолчанию, `--order source` — по ходу исходника). Идёт ходьба — `speed` 2–3 в `plan.json`; почти неподвижный вид — 0,5–0,75.
5. **Под трек.** Есть карта долей (`python3 scripts/track_structure.py <трек> --json beats.json`) — `score ... --beats beats.json --music-in <секунда трека>`: склейка ложится на долю, если та не дальше 0,12 с. Спокойный трек — режь по фразам, а не на каждую долю.
6. **Черновик:** `python3 scripts/highlight_cut.py render "WORK/<проект>/in/<файл>" --plan "WORK/<проект>/out/<имя>-highlight/plan.json"` — немой MP4 1080×1920, 30 fps (горизонталь — `--size 1920x1080`). Звука в черновике нет, и `audio_sync.py --music` сюда не подходит: он кладёт трек под голос. Музыку ставь по `cadence-sound`, цвет и стабилизацию — в `cadence-resolve` (план из `plan.json`).

## 8. Что появится в `WORK/<проект>/out/`

| Файл | Что это |
|---|---|
| `<имя>-cut.mp4` | видео без пауз |
| `<имя>-cut.json` | какие куски оставлены, какие паузы вырезаны (секунды) |
| `<имя>-cut.edl` | тот же монтаж для DaVinci Resolve (CMX3600) |
| `<имя>-cut.srt`, `<имя>-cut.words.json` | субтитры и слова с временем |
| `<имя>-cut-subs.mp4` | видео со вшитыми субтитрами |
| `<имя>-sync.mp4`, `<имя>-cut-music.mp4` + `.json` | звук рекордера, музыка; в JSON — сдвиг и уровни |
| `<имя>-sync-preview/` | три коротких ролика для проверки сведения на глаз |
| `<имя>-takes.mp4`, `.json`, `.edl` | ролик из выбранных дублей, план и проверка, монтаж для Resolve |
| `<имя>-fragments/`, `<имя>-takes-seams/` | куски для поиска повторов, кадры по краям стыков |
| `<имя>-highlight/`, `<имя>-highlight.mp4` | план хайлайта с листом кадров и немой черновик |

В конце покажи человеку список файлов, длину итога и что отпечаток исходника не изменился (`shasum -a 256` ещё раз). Итоговый ролик прогони техпроверкой — `python3 scripts/check_reel.py "WORK/<проект>/out/<итог>.mp4"` — и перескажи строки «стоп» и «внимание»; что смотреть глазами — `guides/BEFORE-POSTING.md`.

## Куда дальше

- Нужен ручной монтаж: подвинуть резы, добавить перебивки, цвет — передай в `cadence-resolve`. Ему понадобятся исходник из `in/` и `<имя>-cut.edl` (импорт таймлайна: File → Import → Timeline). Проект Resolve сам не открывай и не меняй.
- Нужен звук по событиям: вжухи на переходах, щелчки на появлении текста — передай в `cadence-sound` с готовым `<имя>-cut.mp4` и `<имя>-cut.json`.

## Не делать

- Не перезаписывать и не переименовывать исходник; `--out` на тот же файл скрипты отклоняют.
