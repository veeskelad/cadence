# Вход и последовательность результатов

## Назначение

Показать один источник и несколько производных состояний или результатов. Семейство: преобразование.

## Входные данные

Входной объект, preview, последовательность различных состояний frames[], порядок, отношение происхождения.

## Параметры и компоновка

Общий perspective parent; preview фронтальный; вход допускает небольшой yaw; N окон определяется числом результатов; filmstrip шире одного кадра.

## Контракт исполнения

Все размеры заданы относительно ширины W и высоты H кадра. Пак задаёт цвета и шрифты; safe zones берутся из design/tokens.json и ограничений сцены. До движения загрузить шрифты и материал, вычислить окончательный layout. Для Instagram Reels/TikTok 9:16 рабочая безопасная область важного содержания: x=0.06W…0.82W, y=0.15H…0.75H (при 1080×1920 примерно x=65…886, y=288…1440). Это консервативные рабочие поля, не официальная универсальная спецификация. Заголовки, captions, CTA, логотип, лицо и существенные детали помещаются в пересечение этой области с safe zones токенов и сцены. Фон и несущественный декор могут доходить до края. Геометрические defaults ниже адаптировать к доступному прямоугольнику; не сохранять размер карты ценой перекрытия интерфейсом. При наличии фактического UI уточнить поля.

Расписание задаёт start, entry, hold, exit и смысловые события; длительности выбираются по речи, читаемости и сетке музыки, фиксированная длина сцены не требуется.

Локальный progress `u=clamp((t−start)/duration,0,1)`; при t<start вернуть исходное состояние; при duration=0 и t≥start состояние сразу конечное. `E(u)=1−(1−u)^3` для мягкой остановки, `E(u)=u` для равномерного движения; `lerp(a,b,u)=a+(b−a)u`. Один кадр полностью вычисляется из t, входных данных и seed. Без накопленной физики, Date.now, независимых CSS timers и несидированной случайности.

## Слои

Входная плоскость → preview → полоса с отдельными окнами → фиксированное пояснение. Перфорация декоративна и не перекрывает материал.

## Порядок анимации

Вход: источник предъявляется. Действие: preview возникает как его результат, состояния последовательно занимают окна ленты. Hold: нужные окна читаются при остановке или умеренном ходе. Выход: выбранное окно становится героем следующей сцены.

## Вычисление состояния

window_i содержит отдельную текстуру frames[i]; x_i(t)=xBase+i×pitch−travel(t). Для кадров собственной композиции t_i заранее задано и уникально.

## Критерии результата

В окнах действительно разные состояния; порядок не меняется; неподвижный заголовок не едет вместе с лентой. Проверить начало, события изменения, завершение каждого entry/exit, стыки по соседним кадрам и устойчивый финал в итоговом MP4. Если внутри есть видео, проверить, что оно играет. Один и тот же t после разных порядков seek должен давать одинаковую композицию.

Проверить экспортированный файл через ffprobe: по умолчанию 1080×1920, SAR 1:1, DAR 9:16 и правильная ориентация с учётом rotation metadata. Промпт и скриншот телефона не подтверждают параметры файла; возможность перемещения в Instagram не доказывает ошибку пропорций.

## Когда отказаться и как исправлять

Для независимых объектов без общего происхождения выбрать галерею. Если окна повторяют один кадр, исправить выбор состояний, а не скорость ленты. Если локальная диагностика не объяснила сбой, искать в публичной официальной документации конкретного API или renderer по симптому и версии. Исправить причину, затем повторить проверку затронутого участка в итоговом ролике.
