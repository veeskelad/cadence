# Число и раскрывающийся график

## Назначение

Показать изменение количества с понятной конечной величиной и источником данных. Семейство: время.

## Входные данные

startValue, endValue, unit, источник/дата если нужны, dataPoints[], диапазоны осей.

## Параметры и компоновка

Контраст числа выше фона; разряды помещаются в конечном layout; координаты графика нормируются по данным; узлы появляются по ходу линии.

## Контракт исполнения

Все размеры заданы относительно ширины W и высоты H кадра. Пак задаёт цвета и шрифты; safe zones берутся из design/tokens.json и ограничений сцены. До движения загрузить шрифты и материал, вычислить окончательный layout. Для Instagram Reels/TikTok 9:16 рабочая безопасная область важного содержания: x=0.06W…0.82W, y=0.15H…0.75H (при 1080×1920 примерно x=65…886, y=288…1440). Это консервативные рабочие поля, не официальная универсальная спецификация. Заголовки, captions, CTA, логотип, лицо и существенные детали помещаются в пересечение этой области с safe zones токенов и сцены. Фон и несущественный декор могут доходить до края. Геометрические defaults ниже адаптировать к доступному прямоугольнику; не сохранять размер карты ценой перекрытия интерфейсом. При наличии фактического UI уточнить поля.

Расписание задаёт start, entry, hold, exit и смысловые события; длительности выбираются по речи, читаемости и сетке музыки, фиксированная длина сцены не требуется.

Локальный progress `u=clamp((t−start)/duration,0,1)`; при t<start вернуть исходное состояние; при duration=0 и t≥start состояние сразу конечное. `E(u)=1−(1−u)^3` для мягкой остановки, `E(u)=u` для равномерного движения; `lerp(a,b,u)=a+(b−a)u`. Один кадр полностью вычисляется из t, входных данных и seed. Без накопленной физики, Date.now, независимых CSS timers и несидированной случайности.

## Слои

Фон → оси/линия → marker → число → единица и пояснение.

## Порядок анимации

Вход: показать смысл показателя. Действие: число и линия раскрываются одной функцией progress. Hold: конечное значение стабильно, источник доступен. Выход: число остаётся частью вывода либо передаётся следующей диаграмме.

## Вычисление состояния

Два режима задаются явно. Для самостоятельного конечного числа: value=lerp(startValue,endValue,E(u)), precision берётся из единиц/данных, display=formatted(value,precision); соседняя декоративная линия раскрывается по своей длине и не обозначает историю значения.

Для реальных данных: q=lerp(timeMin,timeMax,u); найти соседние точки с times a≤q≤b и вычислить v=lerp(valueA,valueB,(q−a)/(b−a)). Marker находится в screen(q,v), число отображает v с нужной точностью. Вычислить длину пути до этого marker как сумму пройденных сегментов плюс долю текущего сегмента; dashoffset=totalLength−coveredLength. На криволинейном пути использовать заранее рассчитанную таблицу (time,point,arcLength) и её интерполяцию. Дубликаты времени заранее объединить по выбранному правилу; пустой набор не рисовать. Нельзя использовать один u как время данных и как долю общей длины дуги без такого преобразования.

## Критерии результата

Итог соответствует данным; marker на линии; единицы не меняются; узлы не прыгают из-за случайности. Если данные условные, метка «Пример» видна всё время, пока виден график; реальные числа сверены с источником и единицами. Проверить начало, события изменения, завершение каждого entry/exit, стыки по соседним кадрам и устойчивый финал в итоговом MP4. Если внутри есть видео, проверить, что оно играет. Один и тот же t после разных порядков seek должен давать одинаковую композицию.

Проверить экспортированный файл через ffprobe: по умолчанию 1080×1920, SAR 1:1, DAR 9:16 и правильная ориентация с учётом rotation metadata. Промпт и скриншот телефона не подтверждают параметры файла; возможность перемещения в Instagram не доказывает ошибку пропорций.

## Когда отказаться и как исправлять

Не придумывать показатель ради эффекта. При расхождении числа и линии проверить, что обе величины относятся к одной шкале и моменту. Если локальная диагностика не объяснила сбой, искать в публичной официальной документации конкретного API или renderer по симптому и версии. Исправить причину, затем повторить проверку затронутого участка в итоговом ролике.
