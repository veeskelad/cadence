# Пространственный веер карточек

## Назначение

Несколько связанных вариантов, среди которых нужно выделить главный. Семейство: набор и иерархия.

## Входные данные

cards[], activeIndex, порядок чтения, тексты или собственные изображения; N определяется содержанием.

## Параметры и компоновка

N=3–5 для одного экрана; ширина hero=0.45W, side=0.4W; x=0.5W и 0.3W/0.7W; perspective=1.4W; yaw=±18°, roll=±4°; глубина hero=0.08W, side=0, far=−0.12W.

## Контракт исполнения

Все размеры заданы относительно ширины W и высоты H кадра. Пак задаёт цвета и шрифты; safe zones берутся из design/tokens.json и ограничений сцены. До движения загрузить шрифты и материал, вычислить окончательный layout. Для Instagram Reels/TikTok 9:16 рабочая безопасная область важного содержания: x=0.06W…0.82W, y=0.15H…0.75H (при 1080×1920 примерно x=65…886, y=288…1440). Это консервативные рабочие поля, не официальная универсальная спецификация. Заголовки, captions, CTA, логотип, лицо и существенные детали помещаются в пересечение этой области с safe zones токенов и сцены. Фон и несущественный декор могут доходить до края. Геометрические defaults ниже адаптировать к доступному прямоугольнику; не сохранять размер карты ценой перекрытия интерфейсом. При наличии фактического UI уточнить поля.

Расписание задаёт start, entry, hold, exit и смысловые события; длительности выбираются по речи, читаемости и сетке музыки, фиксированная длина сцены не требуется.

Локальный progress `u=clamp((t−start)/duration,0,1)`; при t<start вернуть исходное состояние; при duration=0 и t≥start состояние сразу конечное. `E(u)=1−(1−u)^3` для мягкой остановки, `E(u)=u` для равномерного движения; `lerp(a,b,u)=a+(b−a)u`. Один кадр полностью вычисляется из t, входных данных и seed. Без накопленной физики, Date.now, независимых CSS timers и несидированной случайности.

## Слои

Фон → дальние карточки → боковые → hero → неподвижный заголовок. У всех карт один родитель перспективы и фиксированный порядок перекрытий. Сначала разложить конечные позиции; текст hero оставить почти фронтальным.

## Порядок анимации

Вход: задние карты садятся в позиции, затем hero и его содержание; stagger выражается долей entry. Основное действие: activeIndex переводит выбранную карту к hero-позиции, остальные уступают место; без нового события карты стоят, пока их читают. Выход: текст уходит, плоскости собираются к общему якорю или закрываются общей маской.

Для N=3 использовать hero и две side-позиции. Для N=4 добавить far-left (x=0.2W,y=heroY+0.03H,z=−0.12W,width=0.34W); для N=5 добавить far-right симметрично. По мере роста N уменьшать боковые размеры до сохранения safe zones. Perspective применяется один раз к общему родителю; у детей только локальные transform.

При смене activeIndex в DOM использовать отдельный foreground hero: на этапе закрытия/уменьшения старого hero подменить его содержание и раскрыть новый. В боковых slots обновить порядок остальных карточек. Не переносить произвольный DOM-ребёнок впереди других только через translateZ в плоском stacking context. Для настоящей 3D-сцены применять depth sorting внутри одного 3D-контекста, не смешивая его с плоским z-index.

## Вычисление состояния

Матрица карты = Perspective(P) × Translate(x,y,z) × RotateY(yaw) × RotateZ(roll) × Scale(s). Все компоненты интерполируются от заранее заданных начальных значений к конечным.

## Критерии результата

Hero не перекрыт; буквы не зеркалятся; z-порядок не прыгает; общий заголовок не наследует наклон карт. Проверить начало, события изменения, завершение каждого entry/exit, стыки по соседним кадрам и устойчивый финал в итоговом MP4. Если внутри есть видео, проверить, что оно играет. Один и тот же t после разных порядков seek должен давать одинаковую композицию.

Проверить экспортированный файл через ffprobe: по умолчанию 1080×1920, SAR 1:1, DAR 9:16 и правильная ориентация с учётом rotation metadata. Промпт и скриншот телефона не подтверждают параметры файла; возможность перемещения в Instagram не доказывает ошибку пропорций.

## Когда отказаться и как исправлять

Когда нужно одновременно прочитать длинные тексты всех вариантов, выбрать плоскую сетку. При нечитаемости уменьшить yaw и число карт, а не увеличивать blur. Если локальная диагностика не объяснила сбой, искать в публичной официальной документации конкретного API или renderer по симптому и версии. Исправить причину, затем повторить проверку затронутого участка в итоговом ролике.
