# Система поведения анимации

## Смысл и бюджет внимания

На сцену выбрать главное изменение, затем минимальные поддерживающие реакции. Различать цель: подтверждение причины, пространственная ориентация, раскрытие информации, объяснение времени, сравнение или выразительный акцент. Если движение отвлекает от данных и текста, уменьшить его область/амплитуду или остановить. Повторяющаяся фонова́я анимация оправдана только содержанием: циклом процесса, течением времени или выбранным материалом.

Для интерактивной оболочки отдельно учитывать частоту действия, клавиатуру, возможность прерывания, focus и предпочтения уменьшенного движения. В MP4 нажатие является событием сценария; зритель не инициирует его. Поэтому частота кликов приложения не задаёт длительность видеосцены, а CSS hover не является источником её clock.

## Контракт состояний и времени

Каждый элемент имеет начальное/конечное состояние и функцию от времени. Геометрия рассчитывается после загрузки материалов и шрифтов, но до обращения к промежуточным кадрам. Проверить bounds, владельца transform, clipping и координаты родителей.

```text
u = clamp((t−start)/duration, 0, 1)
state(t) = interpolate(from, to, easing(u))
```

При t<start — исходное состояние; при duration=0 и t≥start — конечное состояние; отрицательные длительности и нечисловые параметры отклоняются. Кадр не зависит от предыдущего вызова. Для последовательности фаз использовать отдельные локальные u; на границе последняя величина предыдущей фазы совпадает с первой следующей. Для реальных данных и пути преобразовать время в координаты и длину дуги по контракту карточки, а не общей декоративной кривой.

## Выбор функции движения

| Поведение | Закон | Контроль |
|---|---|---|
| Лента, playhead, равномерный маршрут | linear | скорость соответствует времени/данным |
| Прибытие к устойчивому объекту | монотонное торможение | большую часть пути проходит раньше, мягко садится |
| Смена места в одной сцене | разгон и торможение | промежуточный путь не заслоняет читаемое |
| Уход в продолжение склейки | закон выхода текущего пакета | направление и скорость согласованы со входом следующего |
| Отдача, масса, возвращение после воздействия | затухающая реакция | перелёт соответствует предмету и не колеблет буквы |
| Раскрытие сравнения или маски | монотонный reveal | видимая граница совпадает с указателем |

Базовое торможение без новой библиотеки: E(u)=1−(1−u)^3. Симметричная плавная смена: E(u)=u²(3−2u). Сохранить кривые существующего пака, когда они выполняют функцию. Для cubic-bezier x означает время, y прогресс: решать x(s)=u и брать y(s), а не считать y(u) напрямую. Не переносить чужую точную таблицу кривых как неизменный стандарт бренда.

## Физическая реакция

Пружина нужна, когда состояние следует за воздействием или ощущение массы существенно. Не пружинить каждый титр по умолчанию. Для непрерываемого видеособытия предпочтительна детерминированная аналитическая функция; использовать существующий spring/springTrack движка, если его контракт подходит.

До начала события вернуть x0; после подтверждённой посадки — устойчивый target без видимого скачка. Обозначить x0, цель, начальную скорость, собственную частоту и затухание. Для underdamped режима r=t−start, ωd=ωn×sqrt(1−ζ²):

```text
x(r)=target+exp(−ζωn r)×[A cos(ωd r)+B sin(ωd r)]
A=x0−target
B=(v0+ζωn A)/ωd
```

ζ<1 даёт перелёт, ζ=1 критический возврат без колебаний, ζ>1 более медленное приближение. Формула выше применима только 0<ζ<1; для остальных режимов использовать отдельное решение или функцию движка. Для критического режима x=target+(A+(v0+ωn A)r)exp(−ωn r). Большая ωn сокращает время реакции; большая масса при неизменной жёсткости его увеличивает. Параметры задаются характером объекта и временем посадки, а не именем модной библиотеки. Перелёт не должен обрезать safe area или нарушать читаемость.

Если сценарное действие прерывает предыдущую реакцию, вычислить x и скорость старой функции на момент нового события и использовать их как from/v0 новой. Не начинать снова с исходной позиции. События упорядочены; их сегменты выбираются по t, без накопленного состояния.

## Якорь, идентичность и путь

Anchor задаётся действием: меню из точки вызова, выделение из bounds слова, крышка из шарнира, раскрытие детали из её места. Центральный origin уместен, когда объекта-вызова нет. Проценты translate в DOM относятся к собственным размерам элемента; координаты кадра и parent space нельзя смешивать.

При превращении сохранить идентичность через общую оболочку или узнаваемый элемент. Для FLIP: измерить bounds A и B, отрисовать layout B, применить обратный transform A→B, затем убрать его до identity. Отдельно защитить текст от растяжения и компенсировать радиус, если требуется. View Transition/React layout API не обязательны: алгоритм исполним в текущем renderer.

Путь взгляда: конец одного действия → начало следующего в связанном месте. Новая цель видна до полёта. Для реального обратного действия допустима обратная траектория; обычное продолжение ролика сохраняет главное течение. Не требовать симметричного выхода, когда по сценарию объект передаётся дальше.

## Порядок элементов и читаемость

Stagger объясняет порядок или принадлежность списка. Входы могут перекрываться, но последнее важное слово получает полный hold. Для обычного текстового каскада применяется motion-laws: интервалы сокращаются ×0.84, opacity/blur не добавляются. Равномерный stagger для равномерных шагов — отдельный режим: общий span выбран из сценария; при N>1 event_j=start+j×span/(N−1), при N=1 событие start. Отдельный jitter случайных задержек не добавлять.

Число уже показанных строк, длина текста и время чтения ограничивают каскад. После посадки информация стабильна. Если две группы конкурируют за взгляд, развести их по времени или снизить второстепенный контраст. Длительность выхода обычно меньше чтения/входа, но зависит от передачи через стык. Доли музыки не сокращают необходимое время понимания; использовать несколько долей для одной фразы.

## Свойства и стоимость

Transform/opacity удобны для движения плоскостей, но маски, радиус и изменение содержимого нужны для некоторых смысловых действий. Анимировать только нужные свойства; не использовать transition:all. Прямое изменение width/height оправдано морфом с пересчитанной вёрсткой; где эффект достигается FLIP без деформации — предпочесть его. Не вводить абсолютный запрет, делающий карточку невоспроизводимой.

Blur, тени, фильтры, WebGL и подкадровый смаз ограничить необходимой областью. Текст держать вне blur-группы. Смаз движения не заменять общим расфокусом. Не считать GPU ускорение доказанным по одному свойству; проверить фактическую сборку. Избегать parent React rerender для каждого тика, случайных значений на кадре, бесконечных timers и неоднозначного завершения.

Все библиотеки должны получать один seek clock. CSS/WAAPI допустимы только с явной привязкой текущего времени и paused состоянием; обычная wall-clock анимация не подходит для покадрового MP4. Ресурсы готовятся до первого render(t), их загрузка не меняет композицию во время рендера.

## Аудит по наблюдаемому дефекту

- Медленно реагирует: слишком поздно начинается причинное действие, кривая задерживает видимый ответ или доезд занимает весь интервал.
- Дёргается: state копится, отрезки не совпадают на стыке, сменяется transform owner, шрифт меняет layout, видео не перематывается.
- Плывёт текст: анимируется родитель без компенсации или повторно измеряется layout.
- «Резиновое»: слишком большой перелёт/много колебаний для роли предмета.
- Смена бессмысленна: нет связи/якоря, несколько объектов спорят за внимание.
- Отличается после seek: состояние не сбрасывается полной функцией, событие зависит от истории воспроизведения.

Исправлять причину, а не удлинять всё движение. Смотреть в обычном темпе для смысла и отдельно соседние кадры для непрерывности. Приёмка: причина видна, реакция начинается вовремя, цель достигнута, чтение сохранено, стык согласован, повторный seek одинаков, итоговое видео реально играет и имеет корректный формат. Для интерактивной оболочки дополнительно проверить повторное/обратное действие и уменьшенное движение; для MP4 при необходимости подготовить спокойную версию с тем же смыслом.

## Поиск места для движения и словарь назначения

Искать разрыв смысла: причина не получила реакции; новый объект появился без происхождения; последовательность не имеет указателя; сравнение нельзя прочитать; следующий кадр теряет прежний объект. Название эффекта выбирать после этой диагностики. Если разрыва нет и выраженный акцент не нужен, анимация не обязательна.

- Reveal раскрывает содержание через границу; mask определяет видимую область, clip ограничивает её по геометрии.
- Morph меняет форму общего объекта; shared-element переносит узнаваемый объект между компоновками; локальная подмена меняет его содержимое при сохранении носителя.
- Stagger обозначает порядок входов; orchestration согласует разные роли одной цепочки.
- Overshoot означает проход за цель; spring — закон затухающей реакции, не синоним любого перелёта.
- Parallax различает скорости планов; perspective задаёт проекцию глубины. Один без другого возможен.
- Motion blur передаёт интеграцию движения внутри выдержки; depth blur разделяет планы по резкости. Не подменять первое вторым.

Для описания без термина сначала определить наблюдаемое изменение (место, размер, граница, порядок, цвет, инерция), затем указать нужную конструкцию. Не требует обращаться к внешнему глоссарию.

## Смежные контракты

Совместимость (`knowledge/system/compatibility.md`, от корня выпуска) разрешает пересечения с DESIGN и public motion-laws. Новые curve/material параметры сохраняются в scene spec; pack schema не расширяется. Конкретные UI-пороги не являются стандартом видео. Полноценный интерфейс дополнительно использует физическое взаимодействие, платформенные primitives и notification-state; обычный MP4 остаётся чистой функцией renderer.

## Адресная проверка стоимости

Если элемент сдвигается на первом кадре, проверить подготовку шрифта/layout/layer, и только после доказательства использовать will-change для нужного элемента; снять hint после нужного lifetime. Большой UI список виртуализировать/пагинировать по задаче, не проигрывать entrance recycled rows. Повторный layout read/write, inherited parent CSS variables и общий React rerender искать по профилю; локальный style/ref update допустим по архитектуре. Full transform и CSS/WAAPI не гарантируют compositor при любых свойствах и версии; проверить нагрузку и фактический renderer. Прозрачные/blur области уменьшать по роли, не фиксированным универсальным pixel cap. Оптимизация должна сохранять прежние значения и pure seek, а не выдавать более быстрый неправильный кадр.

## Частота и масштаб настоящего интерфейса

Чем чаще повторяется действие, тем меньше его бюджет внимания: сократить путь и длительность, убрать перелёт/торжественный вход; для часто используемого control допустимо не анимировать появление. При этом состояние и подтверждение действия остаются немедленно различимыми. Редкое значимое раскрытие может иметь более выразительную реакцию. Сначала оценить частоту в реальном сценарии, а не каждый компонент изолированно. В MP4 повторение является частью рассказа; частота операций приложения не задаёт длину чтения кадра.

Меню, dialog, popover, button и другие читаемые плоскости не начинать с scale(0): содержимое деформируется и теряет связь с точкой вызова. Если scale нужен, начинать близко к конечному размеру, выбрать origin у причины и защитить текст; можно использовать границу/clip вместо масштабирования букв. Это норма интерфейсной плоскости. Рост точки, частицы или геометрического знака из нуля в MP4 допустим как отдельное смысловое построение; не использовать это исключение для обычного меню.
