# DaVinci Resolve без риска

**Где запускать команды.** Корень Cadence: `${CLAUDE_PLUGIN_ROOT}`. Если выше стоит путь к папке — Cadence стоит плагином: команды этого навыка запускать из этой папки (`cd` туда), свои файлы человека — в `$WORK`, не в ней. Если видна сама запись в фигурных скобках — это папка выпуска или исходников, команды запускаются из неё.

Resolve — для живого видео: монтаж, переходы, эффекты на съёмке, цвет. Моушн кодом — `cadence-motion`, нарезка пауз и субтитры — `cadence-cut`, звук — `cadence-sound`. `$WORK` ниже — рабочая папка человека (как задать — `cadence-motion`, «Где лежат файлы»).

## Главное правило

**Открытый проект человека не менять без копии и его согласия.** Проект Resolve — месяцы чужой работы, а отмена через агента ненадёжна. Порядок всегда один:

1. **Сначала чтение.** Что открыто, какая версия, какие таймлайны. Ничего не создавать и не сохранять.
2. **План словами.** Что именно будет создано или изменено, где, и как откатить.
3. **Копия.** Перед любой правкой существующего проекта — его копия (ниже), и человек видит, где она.
4. **Согласие** на этот конкретный план: «Менять проект «X»? Сначала сделаю копию «X-backup-ДАТА»».
5. **Действие маленькими шагами** и после каждого — перечитать, что получилось.

Безопаснее всего — **новый проект** с понятным именем (`cadence-<проект>`): чужое там не сломать.

## Что умеет агент — три режима

| Режим | Что нужно | Что делает агент |
|---|---|---|
| Ручная передача | ничего, кроме Resolve у человека | готовит файлы (EDL, видео, музыку, субтитры, карту звуков) и пишет пошаговую инструкцию по меню |
| Через скрипты Resolve | Resolve Studio, в настройках **Preferences → System → General → External scripting using: Local** | читает состояние, создаёт новый проект, импортирует медиа и таймлайны, ставит переходы |
| Через MCP-сервер Resolve | сервер уже подключён у человека | то же, что скрипты, но инструментами; правила осторожности — ниже |

Первый раз — всегда ручная передача или новый проект. Режим выбирает человек.

Не искать Resolve и проекты по всему диску. Нужен путь — спросить.

## Шаг 1. Прочитать состояние

**Через MCP:** сначала инструменты статуса и чтения — версия Resolve, открыт ли он, имя текущего проекта, список таймлайнов, текущая страница. Только чтение.

**Через скрипт:**

```bash
python3 scripts/resolve_check.py          # --json для разбора
```

Только чтение. Отвечает, установлен ли Resolve (ищет лишь в стандартной папке или по
`RESOLVE_SCRIPT_API`), отвечает ли он скриптам, какой проект и таймлайны открыты, и
последней строкой — что делать дальше. Resolve не отвечает — скрипт называет настройку
(External scripting → Local); в бесплатной версии — ручная передача.

Ответ `None` на всё подряд — открыто модальное окно (менеджер проектов, диалог сохранения). Попросить человека закрыть окно; агент этого не умеет.

## Шаг 2. Копия перед правкой существующего проекта

- **Руками (надёжно):** в Project Manager — правый клик по проекту → **Export Project…** → файл `.drp` в `$WORK/<проект>/backup/`. Откат — Import Project из этого файла.
- **Скриптом:** `ProjectManager.ExportProject(имя, путь_к_drp)` — только после сохранения проекта человеком.
- Для правки таймлайна внутри проекта — сначала **Duplicate Timeline** (правый клик в Media Pool), работать в дубле.

## Импорт нарезки из `cadence-cut`

`cadence-cut` (скрипт `scripts/silence_cut.py`) кладёт рядом с готовым видео файл `$WORK/<проект>/out/<имя>-cut.edl` — тот же монтаж списком резов (CMX3600). Таймлайн в нём начинается с `01:00:00:00`, клип назван именем исходника.

**Руками:**
1. Новый проект (File → New Project), имя `cadence-<проект>`.
2. До импорта медиа: **File → Project Settings → Master Settings** — частота кадров таймлайна как у исходника. После добавления медиа её не сменить.
3. Перетащить **исходник** (не `-cut.mp4`) в Media Pool.
4. **File → Import → Timeline…** → выбрать `<имя>-cut.edl`. Частота — как у исходника; галку «Automatically import source clips into media pool» снять, раз исходник уже в пуле.
5. Проверить: число клипов на таймлайне равно числу кусков в `<имя>-cut.json`, длина таймлайна — как у `<имя>-cut.mp4`, первый и последний рез — на местах.

**Скриптом** (в новом проекте, после согласия):
```python
mp = project.GetMediaPool()
mp.ImportMedia(["/полный/путь/к/исходнику.mp4"])
tl = mp.ImportTimelineFromFile("/полный/путь/к/имя-cut.edl", {"timelineName": "cut", "importSourceClips": False})
if tl:
    print(tl.GetName(), "| клипов на V1:", len(tl.GetItemListInTrack("video", 1)))
else:
    print("импорт не удался")
```
Сверить число клипов с JSON нарезки. Не сошлось — сказать человеку и предложить ручной импорт, а не «чинить» таймлайн.

## Эффекты Resolve

Пошаговые рецепты (переход из тряски, полосы, сетка 3×3, свечение по карте глубины, негативная вспышка, удар оптикой) — [references/effects.md](references/effects.md). Что агент может поставить скриптом, а что только рукой и чем это заменить — [references/api-map.md](references/api-map.md). Что из этого подтверждено отрендеренным кадром (и на какой версии), протокол пробы и свой шаблон перехода (`scripts/resolve_transition_template.py`) — [references/verified-effects.md](references/verified-effects.md). Ещё приёмы — банк эффектов в `knowledge/effects-bank/`.

Правила для любого эффекта:
- Первый раз — пробный кусок 10–15 с **в новом проекте**, а не в рабочем таймлайне.
- Эффект сделан, только если он виден на **отрендеренном кадре**. Ответ API «готово» и чтение настроек обратно ничего не доказывают: бывало, что настройки читаются, а в рендере эффекта нет.
- Есть референс — кадр рендера ставится рядом с кадром референса и сравнивается глазами:
  ```bash
  ffmpeg -i render.mp4 -i ref.png -filter_complex "[0:v]trim=start_frame=45:end_frame=46,scale=-1:960[a];[1:v]scale=-1:960[b];[a][b]hstack" -frames:v 1 -y compare.png
  ```
- Числа из чужих гайдов подобраны под чужой материал — это стартовые значения, не ответ.
- Вспышки — не больше трёх в секунду (порог безопасности для людей со светочувствительностью).

## MCP-сервер Resolve: как пользоваться осторожно

Если у человека подключён MCP-сервер Resolve (официальный или сторонний), его инструменты **могут менять открытый проект**. Поэтому:

- Начинать с инструментов статуса и чтения. Проверка связи — не разрешение на правку и не повод запускать второй Resolve.
- Перед записью — тот же план, копия и согласие, что и выше.
- Один агент за раз: многошаговую правку не вести параллельно с другим агентом или скриптом.
- Не утверждать «проект закрыт» или «сохранено», пока это не проверено чтением.
- Операция упала, прошла частично или с непонятным ответом — **сначала перечитать состояние**. Не повторять её вслепую и не прогонять через другой инструмент.
- Если сервер даёт «безопасный» и «небезопасный» запуск скриптов — брать безопасный, пока не нужен доступ к файлам системы.
- У одних серверов есть лимит времени на вызов (около минуты): долгий рендер запустить одним вызовом и опрашивать отдельными.
- Все вызовы подряд отвечают ошибкой — не перезапускать Resolve по кругу. Остановиться и сказать человеку.
- Рендерить в обычном режиме с открытым окном и сохранённым именованным проектом; у безымянного `Untitled Project` сохранение не срабатывает и вызывает диалог.
- Файлы проекта Resolve (`.drp`, база) напрямую не править, пока проект открыт.

## После каждого действия

Перечитать и сообщить факты: создан ли объект, сколько дорожек и клипов, какая длина, что **не** перенеслось. API или версия не дают сделать шаг — остановиться и предложить ручной путь. Не изображать успех.

## Чего не делать

- Не менять открытый проект без копии и согласия.
- Не трогать чужие таймлайны, bins, Media Pool и настройки без отдельного разрешения.
- Не править проект, пока Resolve в модальном окне или в режиме без интерфейса.
- Не ставить плагины, шаблоны и программы, не скачивать ничего без согласия.
- Не называть эффект готовым без отрендеренного кадра.
- Не публиковать.
