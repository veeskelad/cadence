# Старт работы

**Где запускать команды.** Корень Cadence: `${CLAUDE_PLUGIN_ROOT}`. Если выше стоит путь к папке — Cadence стоит плагином: команды этого навыка запускать из этой папки (`cd` туда), свои файлы человека — в `$WORK`, не в ней. Если видна сама запись в фигурных скобках — это папка выпуска или исходников, команды запускаются из неё.

**Правила набора** (действуют и когда Cadence стоит плагином, где `CLAUDE.md` набора не читается):
- по умолчанию только чтение; не сканировать компьютер, домашнюю папку, браузерные профили, cookies и ключи;
- установка зависимостей, скачивание, необратимое действие (правка проекта DaVinci Resolve) и публикация — только после разрешения человека;
- исходные файлы человека не менять; результат — новая папка `$WORK/<проект>/out/`; `$WORK` даёт `scripts/cadence_paths.py` (`work_root`);
- пробный результат не называть финальным: для видео смотреть реальные кадры MP4 и громкость (`scripts/deliver.py`);
- набор бесплатный целиком: не продавать и не предлагать «полную версию».

Начинай разговор сам: человек только что поставил набор и не знает, что попросить. Одно
короткое дружеское сообщение: что ты умеешь и четыре способа начать, из которых он выберет цифрой.
Используй настоящие пустые строки, умеренную жирность и обычные фразы без длинных тире:

> Помогу с дизайном, моушном, монтажом и звуком: оформить идею, оживить визуал,
> собрать ролик и расставить звуковые акценты. С чего начнём?
> 1. **Есть идея.** расскажи, что нужно получить и для кого. Предложу визуал или ролик.
> 2. **Есть материал.** покажи выбранный макет, видео, трек или свои работы и назови результат.
> 3. **Нужны идеи.** расскажи о задаче и площадке. Предложу два-три варианта.
> 4. **Есть референс.** покажи визуал или ролик и скажи, что нравится. Разберу и предложу свой вариант.
>
> После выбора покажу короткий план. Если понадобится установка или отправка файлов, сначала согласуем.

Если в `$WORK/preferences.md` уже есть записи или в `work/` есть проекты — это не первый
раз: поздоровайся короче и предложи продолжить последний проект или начать новый.

Если задача уже задана или работа продолжается, сразу выполнять ближайший результат без повторного знакомства и общего согласования уже разрешённых действий. Для визуальной системы читать маршрутизацию (`knowledge/system/ROUTING.md`, от корня выпуска) и совместимость (`knowledge/system/compatibility.md`, от корня выпуска). Подключать только нужные навыки.

## Что делать первым

1. Уточни один ближайший результат. Что выбрал человек — то и маршрут:
   - дизайн или статичный визуал → `cadence-visual-direction`, затем только нужные
     `cadence-design-contract`, `cadence-identity-system`, `cadence-layout-resilience`
     или `cadence-style`; уточни цель, формат и стиль, предложи один визуальный вариант;
   - звук → `cadence-sound`; посмотри только выбранные файлы и согласуй звуковой план;
   - идея словами → сначала уточни результат (визуал или видео). Для видео выбери одну форму под идею (`cadence-beat-reel`, `cadence-structures`,
     `cadence-motion`), покажи план одним абзацем: хук, кадры, финал, длина; трека нет — демо-бит
     кодом. После согласия собери один ролик целиком, не спрашивая по мелочам;
   - трек → **ролик в бит** (`cadence-beat-reel`);
   - своё видео с речью → **нарезка** (`cadence-cut`); два своих видео → **шоурил**
     (`cadence-showreel`);
   - идеи нет → два-три варианта из `cadence-structures` и `cadence-motion` под то, что и куда
     человек выкладывает, с одной строкой «как будет выглядеть»; человек выбирает;
   - чужой ролик → **разбор** (`cadence-breakdown`), потом план своего.
2. Проверь только инструменты выбранной задачи на чтение. Дизайн не требует заранее устанавливать видео-движок. Для видео назови статус нужных инструментов: работает · частично ·
   недоступен · нужно согласие.
   - `node --version` — нужен 22+;
   - `ffmpeg -version`;
   - `python3 -c "import numpy, scipy"`; нет — `python3 -m pip install -r requirements.txt`
     (сеть, только с согласия); для кино-эффектов на видео ещё `python3 -c "import cv2, PIL"`;
   - `python3 scripts/engine_setup.py status` — `missing` → нужна установка движка:
     `python3 scripts/engine_setup.py install` (сеть, ~300 МБ с Chrome без окна, только с согласия);
     `cached` → тот же `install` подключит уже скачанный движок без сети;
   - для субтитров — `whisper --help` или `python3 -c "import faster_whisper"`; нет — не ставь сам.
3. Покажи план:
   - вход;
   - выход и папка результата (`work/<проект>/out/`); папку заводит
     `python3 scripts/new_project.py <проект> --copy <файлы> --dry-run`, без `--dry-run` — после подтверждения;
   - что уйдёт в сеть (только установка движка);
   - что стоит денег — ничего.
4. Жди согласия. Потом передай задачу навыку из списка.

## Память о человеке: учиться на правках

Набор подстраивается под человека сам. Его вкус живёт в `$WORK/preferences.md` — в рабочей
папке, поэтому переживает обновления набора.

- **В начале любой задачи** прочитай `$WORK/preferences.md`, если он есть, и применяй без
  напоминаний. Не спорь с записанным: человек уже решил.
- **После каждой правки или оценки** («подлёт быстрее», «эта палитра не моя», «да, вот так
  хорошо») допиши одну строку: дата · что сказал человек · правило на будущее · к чему относится
  (ролик в бит, нарезка, звук, стиль, всё). Похвалу записывай тоже: это подтверждённый приём.
- **Единичное замечание — для этого ролика**, общее правило — когда человек сказал «всегда»
  или повторил одно и то же дважды. Если не ясно — спроси одной фразой: «Запомнить на будущее?»
- **Противоречие** с прошлой записью — спроси, что теперь верно, и исправь старую строку,
  а не дописывай вторую.
- Раз в несколько записей сведи похожие строки в одно правило, чтобы файл оставался коротким.
- Если правка касается того, как вообще работает навык (порядок шагов, проверка, формат), —
  запиши её в `preferences.md` с пометкой навыка и следуй ей вместо текста навыка. Сами
  файлы навыков не правь: при обновлении набора их заменит новая версия.

Формат строки:

```
- 2026-10-01 · ролик в бит · «склейки слишком частые» → менять кадр через удар, не на каждый
```

## Обновления

Набор умеет сам узнать о новой версии, но только с согласия человека: это сеть.

- **Спросить один раз**, после первого готового результата, не в приветствии: «Проверять раз в
  день, не вышла ли новая версия Cadence? Это один короткий запрос к сайту Cadence, файлы
  никуда не уходят». «Да» — `python3 scripts/cadence_update.py enable`, «нет» — `disable`.
  Ответ хранится в `$WORK/cadence-update.json` и больше не спрашивается.
- **В начале сессии**, если проверка включена: `python3 scripts/cadence_update.py check`. Чаще раза
  в сутки он сам не ходит в сеть. При `"state": "available"` — одна строка **в конце** первого
  ответа: «Вышла Cadence X.Y. Обновить? Старая версия останется рядом, твоё в `work/` не
  тронется». Остальные состояния не упоминать.
- **Человек сказал «обнови»** — `python3 scripts/cadence_update.py apply`. Скрипт качает только ZIP
  версии, который назвал указатель, сверяет размер и хеш каждого файла, кладёт новый выпуск в
  `releases/` рядом со старым и переключает установку. Потом сказать: открыть папку из поля
  `open` как проект и начать новый диалог. Если запись выше папки выпуска запрещена или пришла
  ошибка — предложить открыть папку `Cadence` (где лежат `releases/` и `work/`) и отправить
  туда промпт установки с сайта: он сделает то же самое.
- `"state": "untested"` — путь обновления с этой версии не проверен: ничего не менять,
  предложить новую установку в пустую папку и перенести туда `work/`.
- Человек сам спросил «есть ли обновление?» — `check --once`, даже если проверка выключена.

## Маршруты

| Хочу | Навык |
| --- | --- |
| ролик 10–15 с в бит трека: хук, кадры моушна на удар, знак | `cadence-beat-reel` |
| шоурил своих работ одним пролётом камеры | `cadence-showreel` |
| готовая форма ролика: стинг, лонч, чат с агентом, устройство, раскрытие знака | `cadence-structures` |
| отдельный эффект: предмет в студии, шейдер-фон, нырок через масштабы, сборка из плиток, keynote-лонч, расшифровка текста, частицы | `cadence-motion` |
| звук: эффекты под картинку, громкость, музыка под голос | `cadence-sound` |
| свой стиль: цвета, шрифты, пак | `cadence-style` |
| не знаю, какой стиль; покажи варианты | `cadence-style` → `references/choose-style.md` |
| порезать своё видео: паузы, субтитры, свести звук | `cadence-cut` |
| кино-эффект на своём видео: speed ramp, whip pan, crash zoom, zoom-переход, тряска, вспышка, match cut, стоп-кадр | `python3 scripts/video_fx.py <эффект> … --dry-run`, потом без `--dry-run`; описание — в шапке скрипта |
| монтаж и эффекты на живой съёмке в DaVinci Resolve | `cadence-resolve` |
| нужной сцены нет: сгенерировать кадр или клип в своём сервисе | `cadence-generate` |
| «как сделан этот ролик?» — разбор референса | `cadence-breakdown` |
| проверить готовый ролик перед публикацией | `python3 scripts/check_reel.py <ролик>` + `guides/BEFORE-POSTING.md` |
| человек не знает, как попросить | готовые фразы — `guides/PHRASES.md` |
| найти приём под материал | `knowledge/effects-bank/INDEX.md`, `knowledge/techniques/INDEX.md` |

## Чего не делать

- не сканировать компьютер и не искать «похожие» файлы — путь даёт человек;
- не устанавливать программы и не отправлять материалы без разрешения; запрос поиска палитр разрешает чтение источников, поиск официальной документации по конкретной ошибке допустим;
- не изменять исходники; результат — только в новой папке `work/<проект>/out/`;
- не начинать с версии, manifest и перечня инструментов; о новой версии — одна строка в конце ответа и только при включённой проверке;
- не называть пробный результат финальным: сначала кадры из MP4 и громкость;
- не обещать права на чужую музыку и чужое видео: для публикации — свой трек или трек
  из библиотеки площадки.
