# Разбор чужого ролика → рецепт

**Где запускать команды.** Корень Cadence: `${CLAUDE_PLUGIN_ROOT}`. Если выше стоит путь к папке — Cadence стоит плагином: команды этого навыка запускать из этой папки (`cd` туда), свои файлы человека — в `$WORK`, не в ней. Если видна сама запись в фигурных скобках — это папка выпуска или исходников, команды запускаются из неё.

Задача — превратить чужой ролик в понятный рецепт: что за приём, из чего он собран, на каких кадрах и долях, и какой скилл Cadence сделает такой же на материале человека. Смотреть кадры и считать, а не угадывать по описанию.

## Границы

- **Скачивание по ссылке — только с согласия.** Сначала спросить: «Скачать ролик по ссылке для разбора? Файл ляжет в рабочую папку, после разбора его можно удалить». Скачиваем только свой ролик или публичный ролик для разбора. Закрытые аккаунты, платные курсы и обход защиты — нет.
- **Права не обещать.** Разбор учит приёму. Чужие кадры, музыка, знаки, персонажи и шрифты в ролик человека не переносятся. Ссылка в рецепте — источник приёма, а не разрешение.
- **Установка программ** (`yt-dlp`, `ffmpeg`, `whisper`) — только с согласия: назвать, что ставим, сколько места и как удалить.
- **Нет файла или нет `ffmpeg` — сказать и остановиться.** Не описывать кадры, которых не видел.
- Исходный файл не трогать: всё, что получается, — новые файлы в рабочей папке.

Рабочая папка: переменная `CADENCE_WORK`, иначе `../../work` от корня набора, в dev-репозитории — `./work`. Для разбора — `<рабочая папка>/<проект>/breakdown/`.

## Шаг 1. Паспорт файла

```bash
python3 scripts/inspect_video.py <файл>
```

Длина, размер кадра, звук, громкость, паузы. `--quick` — только метаданные, `--json` — для записи в файл. Скрипта нет — минимум даёт `ffprobe -v error -show_format -show_streams <файл>`.

По паспорту решить: вертикаль или горизонталь, хватит ли разрешения прочитать мелкий текст, есть ли смысл слушать звук.

## Шаг 2. Контакт-лист кадров

Один лист — весь ролик: кадр каждые 2 секунды, время в углу.

```bash
ffmpeg -i <файл> -vf "fps=1/2,scale=360:-2,drawtext=text='%{pts\:hms}':x=6:y=6:fontsize=28:fontcolor=yellow:box=1:boxcolor=black@0.6,tile=4x<строк>" -frames:v 1 <папка>/sheet.jpg
```

`<строк>` = длительность / 2 / 4, с округлением вверх. Если `drawtext` не собран в этом `ffmpeg`, убрать его из цепочки: время считается по позиции кадра на листе.

Где на листе виден интерфейс, промпт, настройки или таймлайн — снять полноразмерный кадр:

```bash
ffmpeg -ss <секунда> -i <файл> -frames:v 1 <папка>/frame-<секунда>.png
```

Быстрый приём на 3–10 кадрах (вспышка, переход) — снять каждый кадр участка: `ffmpeg -ss <начало> -t <длина> -i <файл> <папка>/burst-%03d.png`.

Траекторию, кривую, смаз и порядок появления по листу раз в 1–2 с не определять. На каждый переход и каждое движение — полоса кадров подряд с номером кадра в углу (`<fps>` — частота ролика, `<шаг>` — 1 для переходов, 2–3 для медленных движений):

```bash
ffmpeg -ss <начало> -i <файл> -vf "select='not(mod(n\,<шаг>))',setpts=N/TB,scale=384:-2,drawtext=text='%{eif\:(<начало>*<fps>+n*<шаг>)\:d}':x=4:y=4:fontsize=16:fontcolor=yellow:box=1:boxcolor=black,tile=5x4" -frames:v 1 <папка>/strip-<начало>.jpg
```

## Шаг 3. Склейки

```bash
ffmpeg -i <файл> -vf "scdet=threshold=10,metadata=print:file=<папка>/cuts.txt" -an -f null -
```

Переходы со смазом и плитками дают оценку 0,1–0,4 вместо 0,9: для поиска таких мест вывести оценку каждого кадра (`select='gte(scene,0)',metadata=print:key=lavfi.scene_score:file=<папка>/scene.txt`) и смотреть всплески выше 0,08. В `cuts.txt` записан каждый кадр с оценкой `lavfi.scd.score`; склейки — только кадры, у которых есть строка `lavfi.scd.time`: `grep scd.time <папка>/cuts.txt` даёт их время в секундах. Порог 10 ловит резкие склейки; плавные переходы и склейки на смазе он пропускает — их искать по контакт-листу. Из списка посчитать: число склеек, медианную длину плана, где монтаж ускоряется.

## Шаг 4. Темп трека

```bash
python3 scripts/track_structure.py <файл> --json <папка>/track.json
```

Скрипт берёт звук прямо из видео через `ffmpeg`, нужны `numpy` и `scipy`. BPM, первая доля, дроп, брейки, фразы. Сопоставить со склейками из шага 3: склейки на долях, на каждой второй, на дропе или свободно. Речь в ролике — отдельно, расшифровка через [cadence-cut](../cadence-cut/SKILL.md).

## Шаг 5. Что за приём

Сформулировать одной фразой, что видит зритель, и найти приём:

1. [Банк эффектов](../../knowledge/effects-bank/INDEX.md) — по колонкам «Как выглядит» и «Вход». Приём уже есть — дополнить его рецепт, второй не заводить.
2. [Словарь 424 приёмов](../../knowledge/techniques/INDEX.md): `grep -i "<слово>" knowledge/techniques/INDEX.md`, затем строку целиком в файле раздела.
3. Это не приём, а форма всего ролика — [форматы подачи](../../knowledge/editing/presentation-formats.md).
4. Звук — по событиям: где riser, удар, whoosh, сколько слоёв — [sound design](../../knowledge/sound/sound-design.md).

Отдельно записать, что в ролике реклама и обещания: «бесплатно», «за 30 секунд», «агент сделал сам» без показанного процесса. Это не факты.

## Шаг 6. Рецепт

Заполнить [шаблон рецепта](references/recipe-template.md). Сохранить в `<рабочая папка>/<проект>/breakdown/<приём>.md`. Статус — «из гайда, рендером не проверено», пока приём не собран на материале человека.

В общий банк `knowledge/effects-bank/` рецепт кладётся только по просьбе человека, вместе со строкой в `INDEX.md`. Предупредить: обновление ставит новый выпуск отдельной папкой и свои рецепты туда не переносит, поэтому оригинал остаётся в рабочей папке, и после обновления его можно положить в банк снова.

## Шаг 7. Маршрут исполнения

Назвать один скилл, который сделает приём на материале человека:

| Что получилось | Кто делает |
| --- | --- |
| смена кадров в долю трека, своя фраза | [cadence-beat-reel](../cadence-beat-reel/SKILL.md) |
| пролёт камеры сквозь «вход → результат» | [cadence-showreel](../cadence-showreel/SKILL.md) |
| моушн, текст, частицы, шейдер, 3D-предмет, анонс продукта без съёмки | [cadence-motion](../cadence-motion/SKILL.md) |
| живая съёмка: переход, грейд, эффект на кадре | [cadence-resolve](../cadence-resolve/SKILL.md) |
| паузы, субтитры, синхронизация звука | [cadence-cut](../cadence-cut/SKILL.md) |
| звуковой слой | [cadence-sound](../cadence-sound/SKILL.md) |
| цвета, шрифты, пак стиля | [cadence-style](../cadence-style/SKILL.md) |
| форма всего ролика | [cadence-structures](../cadence-structures/SKILL.md) |
| кадры, которые может создать только модель | генерация (вне Cadence, позже): честно сказать, что Cadence этого не делает, и предложить ближайший вариант монтажом или кодом |

## Ответ человеку

Коротко, обычным языком:
1. Что за приём — одной фразой, и как он называется в словаре.
2. Из чего собран: 3–6 шагов с таймкодами ролика.
3. Числа: длительность, склейки, BPM — только измеренные.
4. Что можно сделать у себя и каким скиллом; что нельзя без генерации.
5. Путь к рецепту и к контакт-листу.
6. Что не удалось увидеть — `unknown`, без догадок.

Предложить один следующий шаг: например, «соберу пробу на твоём видео — 10 секунд». После разбора спросить, удалить ли скачанный ролик и кадры.
