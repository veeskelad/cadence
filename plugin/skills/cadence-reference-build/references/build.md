# Извлечение и воспроизведение

## Достаточность входа

Посмотреть изображение в исходном разрешении. Определить, что наблюдается, что измеряется, что неизвестно. Сопоставить слова с утверждённым текстом: нарисованная генератором надпись не имеет приоритета над входными фактами. Не выдумывать точный шрифт, hidden states, цветовой код или grid из неразборчивой миниатюры.

При неясности: доступный оригинал/полноразмерный лист → увеличение для инспекции → самостоятельный измеряемый вариант в рамках контракта → уточнение существенного неизвестного. Новая генерация имеет смысл только когда её изменение разрешено; не считать её точным увеличением предыдущего изображения.

## Карта измерения

```text
canvas: width/height/aspect
zones: normalized_bounds, role, reading_rank
text: exact_string, line_breaks, font_role, weight_relation, baseline
space: shared_axes, gaps, padding, optical_adjustment
media: asset, fit, crop, focus_point, protected_detail
components: owner, content, radius, border, states_observed
layers: parent, order, clipping, transform_origin
palette: pack_role, measured_or_estimated_value, contrast
behavior: known_event, from/to, clock, anchor, unknowns
fidelity: preserve_exact / preserve_relation / redesign_allowed
```

Bounds нормировать к W/H: x/W,y/H,w/W,h/H. Пропорции и общие оси обычно важнее псевдоточных pixels. Для сцены в другом aspect ratio сохранить порядок чтения и роль, перепланировав доступные bounds; не растягивать весь исходный лист.

## Реализация

1. Сопоставить компоненты с существующими примитивами/библиотекой проекта. Если настоящий интерфейс принадлежит принятой системе, пользоваться его компонентами, не собирать внешне похожие fake controls.
2. Подготовить assets/fonts и измерить строки. Скомпоновать устойчивый конечный кадр. Не начинать с эффектов, скрывающих плохую геометрию.
3. Построить дерево semantic ownership: контейнер держит geometry, текст отдельный, crop отдельный. Одно свойство имеет одного владельца. Добавить layers/clipping из карты.
4. Проверить статическую точность: отношения ширин, оси, межстрочные интервалы, расстояния, границы медиа, читаемость и palette roles.
5. Добавить нужное действие как from/to от единого clock. Hover рисунка не считать реализованным событием MP4; задать событие сценария. Для настоящего интерфейса проверить событие, обратное действие и focus отдельно.
6. Проверить результат на той же композиции и адаптированных форматах. Устранять отклонение в измеряемом свойстве, а не заменять уникальную компоновку удобным шаблоном.

Нельзя сообщать «готово», имея только описание кода. Для запрошенной реализации нужны полные файлы и реальные пути. Вынести повторяющуюся логику в компонент допустимо; оставлять пропущенные компоненты недопустимо.

## Сверка и исправление

Для собственного принятого дизайна сравнить материал и результат в одинаковых bounds. Ошибки сгруппировать: геометрия, текст, цвет, материал, поведение. Исправить сначала потерянную иерархию/содержание, затем измеримые детали. Если принцип изменён для renderer или safe area, назвать изменение и причину; не утверждать pixel-perfect без проверки.

Для Reels/TikTok главный материал внутри x0.06W…0.82W/y0.15H…0.75H. Проверить UI-overlay и cover crops. Файл видео проверить по dimensions/SAR/DAR/rotation, ключевые состояния по MP4, seek повторяем. Для web-preview проверить actual viewport/overflow, keyboard/focus, reduced motion и состояния; screenshot не заменяет это.

Источники поиска при конкретной нерешённой проблеме: официальная документация API текущей версии и локальный renderer. Не отправлять приватное изображение в поиск. Найденную рекомендацию проверить на реальном контракте, не устанавливать новую библиотеку автоматически.

## Устройство интерфейсной реализации

Сначала определить поверхность: marketing/editorial, продуктовая форма, таблица, редактор кода, native app или collaboration. Последние четыре требуют своего функционального контракта; визуальное изображение не заменяет специализированный контрол. В существующем продукте использовать установленную официальную систему компонентов. Эстетическая похожесть не является официальной интеграцией. При недоступной библиотеке не писать несуществующий import; дать совместимое исполнение либо обозначить разрешение, которое требуется.

Для React-подобной среды continuous значения не хранить в состоянии, перерисовывающем весь parent tree. Разделить статическую structure и узкий interactive leaf, проверить поддерживаемый renderer. Подписки/наблюдатели имеют cleanup. В MP4 такие подписки заменяются state(t). Для CSS проверить установленный majorversion и реальный способ конфигурации; не мигрировать project ради инструкции. Изображения/шрифты грузятся с известными размерами и space reservation; local assets предпочтительны, внешние URL не обходят разрешение на сеть.

Для interactive surface проверить семантику control, ясную label, error/help рядом с ним, keyboard/focus, loading/empty/error по контракту, фактическую ссылку/действие и отсутствие неожиданных layout shifts. Основной CTA отличается от второстепенного, readable на фоне, не рассыпается на неудобные переносы. Для dark/light требуемых тем проверить parity roles/contrast; dualmode не обязателен для единственного видеопака. Actual viewport и touch не заменять выводом по desktop screenshot. Профилирование фактического preview отличать от rendercost и bitrate MP4. Для ошибки использовать измерение, а не обещание FPS/GPU по названию CSS property.
